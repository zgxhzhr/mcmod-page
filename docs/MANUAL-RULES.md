# MC百科 页面手写通用规则（最少工具版）

适用对象：**不用我们的流水线（mcauto / mcmodder 系列脚本），只用浏览器**的人。
目标：从零手写一个能过审的模组页 / 资料页。

> **先纠正一个常见误解**：MC百科**原生只有 UEditor 富文本编辑器**，
> 没有「源代码编辑器」。那个开关是第三方用户脚本 **Mcmodder**（作者 Charcoal-Black / 花海）
> 装到篡改猴（Tampermonkey）之后才出现的。所以这份文档叫「最少工具版」而不是「无工具版」——
> 想写合规页面，**至少要装这一个浏览器脚本**，但不需要我们的流水线。

> 除了装脚本这一步，其余全部可以手工完成。

---

## 0. 开工前，先记住这一条

> **从任何地方复制来的文本，先粘进 Windows 记事本（Notepad）一份，再全选复制出来，然后才往百科编辑器里贴。**

原因：网页、Word、QQ、Discord、其他 wiki 复制过来的文本会带**不可见的样式**——
字体、字号、颜色、背景色、行高、缩进、软换行、零宽字符、智能引号。
在编辑器里看不出来，提交后变成：整段字突然变小、某几个字是灰的、
段落之间多出空行、引号变成 `“ ”`、表格塌掉、甚至整段变成富文本块而 `[icon:…]` 不生效。

**记事本会自动剥掉所有富文本格式**，只留纯文本。这一步 10 秒，能省掉一半退回。

贴完顺手检查（编辑器里 Ctrl+F 或粘进记事本时肉眼扫）：

| 检查项 | 症状 | 处理 |
|---|---|---|
| 全角标点混进代码/数字 | `１．`、`＞`、`（）` | 换成半角 |
| 智能引号 | `“ ” ‘ ’` | 换成 `" '` |
| 零宽字符 | 行首有看不见的空格、删不掉 | 整行重打 |
| 连续空格 / Tab | 排版对不齐、表格错位 | 压成单个半角空格 |
| 软换行 | 一行被拆成两行，实际是一段 | 合并成一行 |

## 1. 编辑器：原生只有富文本，必须装 Mcmodder

### 1.1 事实

| 模式 | 从哪来 | 能不能用 |
|---|---|---|
| **UEditor（富文本）** | **百科原生，唯一自带** | ⚠️ 能存页面，但**做不到合规** |
| 源代码编辑器 | 第三方脚本 **Mcmodder** 提供 | ✅ 首选 |
| Markdown 编辑器 | 同一个脚本提供 | 次选（表达不了合并单元格和颜色） |

**为什么原生富文本做不到合规**：`[icon:health=20]` 这类方括号是**纯文本标记**，
只有源代码编辑器会原样保留下来、由站点渲染成图标；
在富文本里它会被当成普通方括号文字，页面上就是一行字 —— 而审核明确要求
「这些要用百科自带的图标而不是手打」。所以纯原生编辑器写不了数值类内容。

**结论：装 Mcmodder 是硬门槛，不是可选项。**

### 1.2 装法（一次性，5 分钟）

```
1. 浏览器装篡改猴（Tampermonkey）扩展
   —— 装完到扩展详情页把「允许用户脚本」打开，否则脚本装了也不执行
2. 装 Mcmodder：github.com/Charcoal-Black/Mcmodder/releases/latest
3. 刷新百科编辑页 → 顶部出现「源代码编辑器」「Markdown 编辑器」开关
4. 勾上「源代码编辑器」，开始贴 HTML
```

⚠️ 只用它的**编辑器开关**，不要用它的 Markdown→HTML 转换：
它遇到 `<code>` / `<blockquote>` 只告警不修正，转出来会打红框。

### 1.3 保存前必须预览

点一次「正文预览」，逐节看一眼：标题有没有变成真标题、表格有没有塌、
图标有没有画出来、链接是不是蓝色可点。

### 1.4 如果实在不能装脚本

只能写**不含数值图标**的页面（纯文字描述界面），并且：

- 不要写「生命值 20 点」「饥饿值 4 点」这种手打数值 —— 会被退回
- 数值类内容留给有脚本的人补
- 表格用 UEditor 的表格按钮建，合并单元格它支持
- 代码块用 UEditor 的代码按钮，语言选对

## 2. 正文能吃什么语法

### 2.1 标签对照（照抄，别自创）

| 要表达的 | 唯一正确写法 | 备注 |
|---|---|---|
| 标题 | `<p>[h1=标题]</p>` … `[h6=]` | 编辑器里看到 `[h3=…]` 是**正常**的，渲染时才变标题 |
| 段落 | `<p>…</p>` | 每段单独包 |
| 表格 | `<table><tbody><tr><th>表头</th>…</tr><tr><td valign="top"><p>…</p></td></tr></tbody></table>` | 表头**必须** `<th>`，不要用 `<td class="firstRow">` |
| 合并单元格 | `<td rowspan="4" valign="top">…</td>` | 粘完预览确认一次 |
| 列表 | `<ul class="list-paddingleft-2"><li><p>…</p></li></ul>` | **必须 `li > p`**；有序列表用 `<ol>` 同一个 class |
| 代码块 | `<pre class="brush:java;toolbar:false">…</pre>` | `brush:` 后面要带语言（`java`/`text`/`shell`），否则编辑器会弹提示 |
| 血量/饥饿值 | `[icon:health=20]` `[icon:food=4]` | **不要**手打「生命值 20 点」「饥饿值 4 点」，审核会退回 |
| 图片 | `<img src="…" alt="…">` | 编辑器会自己补 `_src` |
| 文字颜色 | `<span style="color: rgb(255, 0, 0);">文字</span>` | **默认一个字的颜色都不要加**，只有明确要求才上色 |
| 标题栏/菜单栏指令 | `[ban:title_menu]` 或 `[mark:title_menu]` | 两种写法都可，按原稿保留 |

### 2.2 不支持（会导致红框或结构错乱）

```
<code> 行内代码
<blockquote>
<hr> / --- / * * * / ===   任何分割线（规范第 22 条明令禁止）
```

### 2.3 三条铁律

1. **方括号标记一个都不许删** —— `[icon:…]` `[ban:…]` `[h1=…]` 都是必需标签。
2. **标题序号跟着原文走** —— 原文是 `Ⅰ.` 就保留 `Ⅰ.`，不要改成 `1.`，也不要自己加序号。
3. **只加不删** —— 你只负责补充和修格式，不要把看不懂的段落、标记、注释删掉。

### 2.4 数字与标点

- 条件用半角 `≥ ≤ > <`，不要写全角 `＞`
- 数字/罗马数字后面**不放全角标点**，用 `Ⅰ. ` `1. `（半角句点 + 空格）
- 属性写「饥饿值」，**不写「饱食度」**

## 3. 模组页：只写摘要

### 3.1 红线

> **模组页只写「这个模组是什么、大概怎么玩」。具体到每个方块/物品的数值、机制细节，全部归资料页。**

判断方法：数一下你写的内容里，**主体有几个**。

| 写的东西 | 归属 |
|---|---|
| 模组整体定位、风格、玩法循环、上手建议 | 模组页 ✅ |
| 某个物品/方块的数值、合成、耐久、机制 | 资料页 ❌ |
| 五维/属性表、单机关卡流程、逐条参数 | 资料页 ❌ |

如果资料页还没建：**先在模组页写一句概要 + 建资料页的清单**，不要把所有细节堆在模组页里。

### 3.2 结构

```html
<p>[h1=概述]</p>            ← 全页只有这一个 h1
<p>[h2=xxx]</p>             ← 其余分节一律 h2
…
<p>[h2=画廊]</p>            ← 画廊必须在最后
```

- **一个页面只有第一个 h1**，其余分节用 h2。超过三个 h1 就停下重新划层级。
- 标题按「读者会不会跳着找」来分，不要一节一个 h1 铺满全篇。
- 原文内容必须归到 `[h1=概述]` 下面，**不能散落在标题外面**。

### 3.3 要不要隐藏目录（`[ban:title_menu]`）

```
字数 < 600                        → 加（唯一条件，不看标题数）
600 ≤ 字数 < 900 且 标题 ≤ 3      → 也可以加
其余                              → 不加，让目录显示
```

理由是「目录用来跳着查」：几百字的页面一屏扫完，目录纯占位。

### 3.4 长介绍的两种写法

- 内容确实长 → 用 `[h2=]` 分节，**不要**因为怕麻烦就全禁用标题
- 贴原文 HTML 时 → 图和链接**必须保留**，其余格式（字体、颜色、缩进）可以简化

### 3.5 附言（`remark`）

**只写内容来源，不写操作过程。** 三条排除：

1. 不写括号注释（`（模组无中文语言文件）`）——审核自己能看出来
2. 不写「正文只写/精简了…」——那是你做了什么，不是内容从哪来
3. 不加「新增方块资料页」这种前缀——站点已经标了页面类型

### 3.6 不要写的

- **不写「版本信息」节**（那是站点自动生成的）
- 不写「本模组由 XXX 制作，遵循 MIT 协议」这类通稿（除非确实需要版权说明）
- 不写「小学生感」的清单填空（见 §6）

## 4. 资料页：字段 + 正文

### 4.1 必填字段

| 字段 | 要求 |
|---|---|
| 中文名 / 英文名 | 中文名优先用模组自带 `zh_cn.json` 的译名，别自己翻 |
| 注册名（registerName） | **`modid:path` 形式，不能为空**。空 → 必退 |
| 类型 | 物品 / 方块 / 实体 / 附魔 / 状态效果…按实际类型选 |
| 最大堆叠 / 最大耐久 | 没有就留空，不要填 `0` |
| 创造模式分类 | 用模组里实际的 tab 名 |

### 4.2 正文

- 开头一句话说清「这是什么、有什么用」
- 参数用表格（`<th>` 表头），不要写成大段流水句
- 有合成表的按合成表规范写（输入 → 输出，摆位要能对上）
- 有机制细节的写机制，不要复述 tooltip

### 4.3 图标

**必须用模组自带的贴图，不要用游戏内截图。**

```
原图          16×16（或方块是 16×16 的立方体展开图）
背景          透明（不要填白底 / 黑底）
处理          NEAREST（最近邻）放大 4 倍 → 32×32 / 放大 16 倍 → 128×128
禁止          双线性/双三次放大（会糊）、加阴影、加边框、加文字
```

透明底自查：把图放到深色和浅色两种背景上各看一次，边缘不能有白边/黑边。
方块图标要么是等距渲染图，要么是正视图，**不要 GUI 截图裁出来**。

### 4.4 实体图标：小图标必须是**头像**

这条被审核退回过的原话：

> 「实体小图标要放头像哦，参考原版，如果难以获取可以只添加大图标」

意思是**两个图标位放的东西不一样**：

| 位置 | 放什么 | 尺寸 |
|---|---|---|
| **小图标** | **头像**（头部正面 / 等距头部），参考原版生物图标 | 小图（32×32 或站点要求尺寸） |
| **大图标** | 完整实体渲染（全身/整体外形） | 大图 |

**不要**把全身渲染压小塞进小图标位——那是一眼能看出来的错。
原版风格参照物：僵尸、苦力怕、骷髅在百科里的小图标都是**头**，不是全身。

#### 拿不到头像怎么办

**直接只加大图标，小图标留空。** 审核明确接受这种做法（"可以只添加大图标"）。
宁可缺小图标，也不要拿全身图充数。

#### 手工取头像（无工具版）

1. 解压模组 jar，找实体贴图：
   `assets/<modid>/textures/entity/<名字>.png`
2. 人形 / 方形头模型：头部 UV 通常在贴图**左上区域**（8×8 或 16×16 的一块）
3. 裁出来 → 透明底 → NEAREST 放大到目标尺寸
4. 放深色和浅色背景各看一次，确认没有白边

> 有些模组头是独立贴图（`textures/entity/<名字>_head.png`），优先用那个。

#### 工具产物不能直接当小图标

我们的导出流水线（LMS / IRR）给实体出的图标是**整体渲染**（LMS 固定 128×128，
只有一个 `Icon` 字段，没有头像版本）。所以：

- 实体页的**大图标**可以用工具产物
- **小图标不要用工具产物填**，要么人工裁头像，要么留空

## 5. 语体：把 AI 味去掉

### 5.1 高频 AI 词（命中就改）

```
旨在、致力于、总而言之、综上所述、总的来说、值得一提的是
不仅…而且…、无论是…还是…、从…到…、为…提供了
丰富的、强大的、独特的、完善的、全面的、多样化的
在这个模组中 / 本模组 / 该模组（一句话出现两次以上）
```

### 5.2 三类要删的句式

| 类型 | 反例 | 改法 |
|---|---|---|
| 空泛评价 | 「玩法丰富多样，极具可玩性」 | 说出具体是什么玩法 |
| 对偶排比 | 「不仅能建造，还能探索」 | 直接陈述两个功能 |
| 过度铺垫 | 「在开始之前，我们先了解一下…」 | 删掉，直接讲 |

### 5.3 一句话一个信息

写之前问自己：**这句删掉，读者会少知道什么？** 答不出来就删。

### 5.4 口语对照

| 不要 | 要 |
|---|---|
| 该物品可用于实现…功能 | 拿它右键可以… |
| 具有一定概率触发 | 有 20% 概率触发 |
| 提供了多种选择 | 有 3 种：A、B、C |

## 6. 核实纪律（最容易翻车的地方）

1. **写数量前先数** —— 「共 12 种」就真去数 12 个，不要目测
2. **写数值前看代码/配置，不要猜** —— 耐久、伤害、概率都能在 jar 里找到
3. **写前置前查依赖** —— 模组页的「前置」写错会被退回；宁可不写也别猜
4. **注册名全仓库搜一次** —— 同一个注册名可能被多个模组占用，确认你写的是这个模组的
5. **版本归属要对** —— 某个物品是 1.12 才有的，就不要写在 1.16 的页面上

## 7. 分类与判定

- 模组分类用**站点上已存在的分类名**，一个字都不能差（含全角问号、空格）。
  差一个字就会新建一个近似分类，造成同类分裂。
- 专有名词（模组名、维度名、Boss 名）**保持原样**，不要自己翻译或改写。
- 短页面判定：内容不足以支撑一屏时，考虑合并进父页面，不要硬凑字数。

## 8. 提交前自检（逐条打勾）

**格式**
- [ ] 用的是**源代码编辑器**，不是 UEditor
- [ ] 所有文本都过了一遍记事本（无富文本残留）
- [ ] 点过「正文预览」，标题/表格/图标/链接都正常
- [ ] 表头是 `<th>`，不是 `<td class="firstRow">`
- [ ] 列表是 `li > p`
- [ ] 没有 `<code>` `<blockquote>` `<hr>`
- [ ] 数字/罗马数字后面是半角 `. `
- [ ] 没有全角 `＞`、智能引号、零宽字符

**结构**
- [ ] 全页只有一个 `[h1=]`，其余是 `[h2=]`
- [ ] 画廊在最后
- [ ] 模组页没写「版本信息」节
- [ ] 模组页只写摘要，细节在资料页
- [ ] 原文内容都在 `[h1=概述]` 下面

**内容**
- [ ] 注册名不为空，格式 `modid:path`
- [ ] 数值/数量都核实过，没猜
- [ ] 前置写对了（或没写）
- [ ] 属性用「饥饿值」
- [ ] 图标是模组自带贴图 + 透明底 + NEAREST 放大
- [ ] 没有 AI 高频词（§5.1 过一遍）
- [ ] 附言只写来源，不写过程

## 9. 常见退回原因 → 修法

| 退回理由 | 真正的问题 | 怎么修 |
|---|---|---|
| 「排版混乱」 | 从网页直接粘的富文本 | 过记事本重贴 |
| 「图标不显示」 | 用了 UEditor | 换源代码编辑器 |
| 「数值错误」 | 手打的生命值/饥饿值 | 改 `[icon:health=…]` |
| 「内容过于简略」 | 模组页只有一句 | 补定位/玩法循环/上手建议 |
| 「与资料页重复」 | 模组页写了物品细节 | 下沉到资料页 |
| 「有明显 AI 生成痕迹」 | §5.1 的词 + 排比句 | 按 §5 重写 |
| 「分类错误」 | 自己起了分类名 | 用站点已存在的分类名 |
| 「注册名为空」 | 没填 registerName | 去 jar 里找 `modid:path` |

## 10. 红线（做了基本必退）

```
❌ 用 UEditor 贴 [icon:…] 等方括号标记
❌ 用游戏内截图当图标（带 GUI、带背景、带文字）
❌ 模组页堆物品/方块细节
❌ 删除看不懂的方括号标记或段落
❌ 自己改标题序号、自己加序号
❌ 编造数值、前置、合成配方
❌ 用分割线（--- / <hr>）
❌ 给正文加颜色（除非明确要求）
❌ 英文未翻译的部分留着中英混杂
```

## 11. 一句话流程

```
读模组 → 列清单（物品/方块/实体/机制）
  → 写模组页（只写摘要，画廊最后）
  → 给每个条目建资料页（注册名必填，图标用自带贴图）
  → 全部文本过一遍记事本
  → 源代码编辑器粘贴 → 预览 → 按 §8 自检 → 提交
```
