### 6.10 内容核实：手册会过时，代码才算数

**来源优先级**：Patchouli 手册 > `lang` 的 tooltip > 代码。但**手册可能落后于代码**——实测手册写「空梦基础刻印可在帕朵商店购买（剩下的没有了）」，代码里**12 个基础刻印全部**注册成了商品（`PardofelisShopMenu` 的 `BASE_SIGNET_PRICE` / `REVERIE_BASE_PRICE`）。**冲突时以代码为准，并在正文里给准确数字**。

**两个容易误判的坑**：

1. `ModText.literal("中文原文")` 是**用中文原文反查 lang key** 的。所以同一个效果出现两组数值时，它们就是**两个不同的键**；判断哪组是"活值"要看 **Java 里硬编码的字面量**（如 `131400%`、`5000.0F`）和常量（`baseAttack * 1314.0F`），而不是在 lang 里挑。
2. `item.<ns>.<id>` 查不到名字的物品，先去 `ModItems` 确认它**是否真的注册**；只有贴图没有注册的是遗留文件（`choice_stone` / `fading_embers` / `image_19`），不收录。

**并行核查很值**：把「材料用途 / 数值条件 / 物品获取」拆给多个子代理同时查，每个都要求**报告带 `文件:行号` 证据 + 明确写"查不到"**，比自己顺序翻代码快很多，且能交叉验证（这次三个子代理查出的结论直接改写了 4 条正文）。


## 6.2.2.36 画廊必须在页面最后

审核点名：「2. 画廊后置」。这条独立于标题层级——就算 h1/h2 全对，画廊夹在中间照样退。

### 规则

```
[h1=概述]
…正文…
[h2=分节] …
[h1=画廊]        ← 必须在最末，前面不能再有任何正文
```

`[h1=画廊]` 之后只能是图片表格或图片段落，**不能再出现正文或其它标题**。

### 反例（实测被退）

```
[h1=概述]
[h1=画廊]        ← 夹在第二位
[h1=改动范围]
[h1=六种村庄]
```

审核附言原文：「1.适当添加 h2 标题；2.画廊后置」。两条分开判，改好 h2 不代表画廊自动合规。

### 自检

```powershell
# 标题序列里 画廊 必须是最后一个
Select-String -Path 草稿.html -Pattern "\[h[12]=" | Select-Object -Last 1
```

最后一行的标题不是「画廊」而页面里又确实有画廊 → 顺序错了。


### 6.10.1 一次反编译的结论不算结论

§6.10 讲的是「代码比手册可靠」，但**代码读一遍就信，同样会错**。
本节是核实纪律，适用于所有要写进正文的事实。

#### ① 必须全量反编译，不要只看一个类

模组的行为经常不在你以为的那个类里：

| 你以为在 | 实际常在 |
|---|---|
| `XxxItem` | `XxxEatProcedure` / 事件监听器 / mixin |
| `XxxBlock` | `XxxBlockEntity` / `loot_tables/blocks/*.json` |
| 代码 | `assets/*/lang`、`models/`、`recipes/`、`blockstates/` |

所以流程固定是：**整个 jar 全量反编译 → 全仓库 grep → 再细读命中的类**。

```powershell
java -jar cfr.jar 模组.jar --outputdir 输出目录 --silent true
# 然后全仓库搜，不是搜单个文件
Get-ChildItem 输出目录 -Recurse -Filter *.java | Select-String -Pattern '"item_id"'
```

#### ①.1 全量反编译要有覆盖率证据，不是「我跑过 cfr」 (2026-11-17 补)

「全量反编译」是可验证的：**顶层类数 = 产出 .java 数**。交付前跑这一段，把数字写进 README：

```python
import zipfile
from pathlib import Path
out = Path(r"...\jar-analyze\<mod>")
z = zipfile.ZipFile(r"...\<mod>.jar")
cls = [x for x in z.namelist() if x.endswith(".class")]
tops = {x[:-6].split("$")[0] for x in cls}          # 内部类并入外层
have = {p.stem for p in out.rglob("*.java")}
missing = sorted(t for t in tops if t.split("/")[-1] not in have)
print(f"顶层类 {len(tops)}，已出 .java {len(have)}，缺 {len(missing)}")
assert not missing, missing[:10]
```

29737 实测：1068 个 `.class` → 910 个顶层类 → 910 个 `.java`，缺 0。
**没有这段数字，"全量反编译"就只是一句口头承诺。**

#### ② 一个结论要两条独立证据链

单一来源不下结论。可用的组合：

```
代码参数  +  资源文件（lang / 模型 / 战利品表）
全量 grep +  单个类细读
mojang 映射 + forge 映射（两份交叉对 SRG 名）
```

**失败案例**：SRG 名 `f_196xx_` 如果只查一份映射表就下结论，
一旦偏移一位，「夜视」会被写成「隐身」。必须 client.txt 与 joined.tsrg 两边对上。

#### ③ 第一遍产物不可信，包括自己上一轮写的

交付前回头核一遍。真实案例：

| 案例 | 第一遍结论 | 复核后 |
|---|---|---|
| 苹果箱 | 「纯装饰，不具备存储功能」 | 查 `loot_tables/blocks/apple_crate.json`：破坏掉 8 个苹果，箱体不返还 —— **定位整个错了** |
| 动物谷猫狗表格 | 品种表第二列只有部分行有值 | 逐行核对后补齐（20 行「宠物商人」+ 3 行「自然生成」） |
| Golden Carrot Juice | 饥饿值 1 | 用户质疑 → 回查 `super(1, 0.0f)` 确认是 1 —— 结论对，但**必须能翻出证据** |

#### ④ 每个数字都要能指到来源

| 写进正文的内容 | 必须来自 |
|---|---|
| 饥饿值 / 饱和度 | `FoodProperties` 构造参数（注意实际饱和度 = nutrition × modifier × 2）|
| 药水效果的等级与时长 | `MobEffectInstance(effect, ticks, amplifier)` |
| 掉落物与数量 | `loot_tables/**/*.json` |
| 生命值 / 护甲 | 属性注册（`Attributes.MAX_HEALTH` 等）|
| 注册名 / 名称 | `item.x` / `block.x` 的 lang 键 |
| 配方 | `data/*/recipes/*.json` 的 pattern / key |

**说不出来源的数字不要写**。宁可留空标「待确认」。

#### ⑤ 交付前五问

```
□ 整个 jar 都反编译了吗（不是只反了几个类）？
□ 这个结论有几条独立证据？
□ 每个数字能指到具体哪一行代码 / 哪个 json？
□ 上一轮的结论复核过吗？
□ 有没有「查了一处就下全局结论」的地方？
```

### 6.10.2 有前置就一起反编译

#### 为什么

模组的核心机制**经常不在它自己的 jar 里**。

| 情况 | 机制实际在哪 |
|---|---|
| 附属模组 | 前置本体（好感度/驯养/属性系统都在主模组）|
| 生物/方块扩展 | 前置本体定义了实体与注册表 |
| 兼容联动 | 被联动的那个模组提供接口 |

**只反扩展，会得出「本模组没有实现这套逻辑」的错误结论**，
或者把前置提供的能力写成「本模组提供」。

#### 步骤

**① 读依赖声明，拿到 modId 与版本范围**

```
Forge / NeoForge : META-INF/mods.toml
                   [[dependencies.<modid>]] 里的 modId / versionRange / mandatory
Fabric           : fabric.mod.json
                   depends / recommends
```

**② 按 modId 找下载（Modrinth 优先）**

```powershell
# Modrinth：开放 API，直链无防盗链
Invoke-RestMethod "https://api.modrinth.com/v2/project/<slug>/version"
# 取 [0].files[0].url
```

```
CurseForge：有防盗链，需要代理
  页面  https://www.curseforge.com/minecraft/mc-mods/<slug>/files
  直链  https://mediafilez.forgecdn.net/files/<id//1000>/<id%1000>/<filename>
  或查  https://api.cfwidget.com/minecraft/mc-mods/<slug>
```

**③ 版本必须对得上**

前置的 MC 版本与 loader 要和模组本身一致（看 `mods.toml` 的 `versionRange`）。
不匹配的前置反出来是另一套代码，结论照样错。

**④ 一起解包，同级目录，跨目录检索**

```
jar-analyze/<模组>/
jar-analyze/<模组>-前置1/
jar-analyze/<模组>-前置2/

# 检索时两个目录一起搜
Get-ChildItem <模组>*,<前置>* -Recurse -Filter *.java | Select-String -Pattern '"item_id"'
```

#### 坑

| 坑 | 说明 |
|---|---|
| **传递依赖** | 前置的前置也算（如某 API 又依赖另一个库）|
| **纯 API 前置** | Curios / Patchouli 这类只需看接口签名，收益低但要确认 |
| **版本漂移** | 不同前置版本行为不同，**必须记下确切的版本号**，写进交付说明 |
| **CF 直链防盗链** | 直接 `Invoke-WebRequest` 可能 403，需要 Referer 或走代理；Modrinth 没这问题 |

#### 判定：什么时候必须写「沿用」

如果正文要写某个机制，而这个机制的方法调用落在前置 jar 里：

```
✗ 本模组提供好感度系统，可以培养亲密度
✓ 好感度与驯养沿用 NFF: Girls 本体的体系，本模组只做生物扩展
```

**写错方向比写少更严重**——会把前置的功劳算在扩展头上。

### 6.10.3 技术断言的版本：真实还是猜的（AI 幻觉高发区）

**这一节管的是「我说的话有没有依据」，而不是「我说得对不对」——两者都要，但先要依据。**

AI 最容易在这里编：版本号、类名/方法名、路径、配置项、加载器兼容性、默认值。
编出来的东西**看起来非常合理**，所以审核和我们自己都容易放过去。

#### 硬规则：每条技术断言必须能指到「哪来的」

| 断言类型 | 唯一可接受的依据 | 不接受 |
|---|---|---|
| 支持的 Minecraft 版本 | `mods.toml` / `neoforge.mods.toml` 的 `versionRange`，或 jar 文件名 | 「我记得它支持 1.20」 |
| 加载器 / 依赖 | `mods.toml` 的 `modId="forge"/"neoforge"`、`fabric.mod.json` 的 `depends` | 「应该是 Forge」 |
| 注册名 | lang 的 `item.<modid>.<name>` 键 或 `Registries` 注册行 | 拼写推测 |
| 数值（饥饿/伤害/护甲/耐久） | 构造参数所在行 | 「大概是」 |
| API / 类 / 方法存在与否 | 反编译产物里能 grep 到的那一行 | 「1.21 应该是 xxx」 |
| 外部工具的行为（导出器/脚本/站点弹窗） | 实际跑一次 / 控制台实测 / 抓到的 HTML | 「它一般用 layui」 |
| 目录规范（资源路径、包名） | 原版 jar 或官方文档的结构 | 「以前是 textures/blocks」 |

**说不出来源的，一律写成「可能」或直接不写**（口径见 §10.2.4 的判定表）。

#### 多轮核对：同一件事至少两轮、独立取证

```
第 1 轮：反编译 / 读配置，写下结论 + 证据（文件:行）
第 2 轮：换一种材料再验一次
        · 版本 → 看 mods.toml 的 versionRange 与 jar 名、NeoForge/Forge 的 loaderVersion
        · 类/方法 → 在产物里 grep 符号，确认不是自己拼的
        · 外部行为 → 真跑一次或抓 DOM，而不是从「同类工具一般这样」推
        · 数值 → 反查引用处（谁在用这个值），确认单位与含义
第 3 轮：把结论念给自己听 —— 「如果审核问我要证据，我拿得出来吗？」
```

**只做第 1 轮的结论不能写进正文**，只能当「待核」。

#### 真实案例（全是这一套里踩过的）

| 断言 | 当时怎么想的 | 实际 | 教训 |
|---|---|---|---|
| `IconRenderer-Forge-1.20.1-1.2.0.jar` 能在 Forge 47 上跑 | 名字里写着 Forge | 它是 **mojmap 构建**，需要 NeoForge 20.1；在 Forge（SRG）上直接崩 | 看 jar 名不算证据，要看类里引用 `net.minecraft.*` 还是 `m_*` |
| 站点撤回确认框是 layui | 弹窗长得像 layui | 控制台一查是 **SweetAlert2**（`.swal2-confirm`） | 外部行为必须抓 DOM，不能凭外观 |
| 1.14 的贴图目录可以是 `textures/blocks` | 模组自己就这么写的 | 1.13 起规范是单数 `block` / `item`，游戏内会显示缺省材质 | 「模组这么写」不等于「规范如此」，要看原版结构 |
| 三只恶魔「可以被驯服」 | 类是 `TamableAnimal` | `isFood()` 恒 `false`，**没有驯服物品、实际驯服不了** | 继承关系只是「能不能」的一半，还要看具体实现 |
| 沉重苹果饱和度 | 直接写饥饿值 × 系数 | 点数要 `× 2`（`nutrition × modifier × 2`） | 数值公式也要有出处，别按直觉算 |

#### 交付前自检

```
□ 正文里每个版本号，我能指出它来自哪个文件的哪一行吗？
□ 每个类名 / 方法名，我是在反编译产物里 grep 到的，还是自己拼的？
□ 外部工具的行为，我是跑过 / 抓过 DOM，还是「同类工具一般这样」？
□ 有没有哪句话是「我觉得应该」，却被写成了陈述句？
□ 两条独立证据都指向同一结论吗（还是只有一条）？
```

#### ⑥ 补丁落盘要回读，脚本打的「✓」不算数（2026-11-16 agent 修复实测）

连打三轮 agent 补丁：脚本输出「✓ 三处补丁」编译也过，**源文件其实一个字没变**——
锚点差一个 `private` 就整批没写入，而 print 照样打勾。直到 `git diff` 为空才戳穿。

**硬规矩**：

```
1) 补丁脚本写完必须【重新读文件】断言每处新文本存在，验证不过退出码非 0
2) 改完立刻 git diff --stat，行数不对 = 没打进去
3) 锚点用 repr 打出真实行（缩进/private/CRLF/行尾空格），别照记忆写
4) CRLF 文件先统一换行再处理，正则 \n 匹配不了 \r\n
```

本轮同一件事还栽了两次：正则锚点被 CRLF 击穿一次、被 `private` 修饰符击穿一次。
**「脚本说改了」和「文件真的改了」是两回事，后者要独立证据。**

#### ⑦ 交稿前拿「上一批的专有名词」扫本批（2026-11-16 串档事故）

24115 The Wax 首版正文出现「冬瓜块由**建筑燃烧引擎与杠杆芯片**合成」——
**整句是上一批 23964 AkutoEngine 的注册表内容**（engineChip/buildcraftcore:engine 都在那批的证据表里），
本 jar 实际 `buildcraft` 字样 **0 命中**、冬瓜块根本没有合成配方。
用户一句「建筑的系统是什么意思」才抓住。

同类还有凭印象加码：小冬瓜正文写了「亮度与燃料同冬瓜块」——注册参数里根本没有。

**硬操作**（写正文之前和交稿之前各扫一遍）：

```powershell
# 把最近几批的 modid 与专名拼成表，扫本批全部正文类产物
Select-String -Path 交付目录\*.json,交付目录\*.html -Pattern "上一批modid|上一批专名A|上一批专名B"
```

- 命中的每一处都要当场判断：是本批 jar 里真有过这个词（能指出文件），还是串档
- 正文里每个「A 由 B 与 C 合成」「与某模组联动」句式，必须能在**本 jar** 指出配方/注册文件；指不出就删
- README 证据表里引用的文件路径带错前缀（akutoengine.json 出现在 the_wax 证据行）就是串档信号
