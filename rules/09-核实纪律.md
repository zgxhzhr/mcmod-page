### 6.10 内容核实：手册会过时，代码才算数

**来源优先级**：Patchouli 手册 > `lang` 的 tooltip > 代码。但**手册可能落后于代码**——实测手册写「空梦基础刻印可在帕朵商店购买（剩下的没有了）」，代码里**12 个基础刻印全部**注册成了商品（`PardofelisShopMenu` 的 `BASE_SIGNET_PRICE` / `REVERIE_BASE_PRICE`）。**冲突时以代码为准，并在正文里给准确数字**。

**两个容易误判的坑**：

1. `ModText.literal("中文原文")` 是**用中文原文反查 lang key** 的。所以同一个效果出现两组数值时，它们就是**两个不同的键**；判断哪组是"活值"要看 **Java 里硬编码的字面量**（如 `131400%`、`5000.0F`）和常量（`baseAttack * 1314.0F`），而不是在 lang 里挑。
2. `item.<ns>.<id>` 查不到名字的物品，先去 `ModItems` 确认它**是否真的注册**；只有贴图没有注册的是遗留文件（`choice_stone` / `fading_embers` / `image_19`），不收录。

**并行核查很值**：把「材料用途 / 数值条件 / 物品获取」拆给多个子代理同时查，每个都要求**报告带 `文件:行号` 证据 + 明确写"查不到"**，比自己顺序翻代码快很多，且能交叉验证（这次三个子代理查出的结论直接改写了 4 条正文）。


## 6.2.2.36 画廊必须在页面最后

审核点名：「2. 画廊后置」。这条独立于标题层级——就算 h1/h2 全对，画廊夹在中间照样退。

### 规则

```
[h1=概述]
…正文…
[h2=分节] …
[h1=画廊]        ← 必须在最末，前面不能再有任何正文
```

`[h1=画廊]` 之后只能是图片表格或图片段落，**不能再出现正文或其它标题**。

### 反例（实测被退）

```
[h1=概述]
[h1=画廊]        ← 夹在第二位
[h1=改动范围]
[h1=六种村庄]
```

审核附言原文：「1.适当添加 h2 标题；2.画廊后置」。两条分开判，改好 h2 不代表画廊自动合规。

### 自检

```powershell
# 标题序列里 画廊 必须是最后一个
Select-String -Path 草稿.html -Pattern "\[h[12]=" | Select-Object -Last 1
```

最后一行的标题不是「画廊」而页面里又确实有画廊 → 顺序错了。


### 6.10.1 一次反编译的结论不算结论

§6.10 讲的是「代码比手册可靠」，但**代码读一遍就信，同样会错**。
本节是核实纪律，适用于所有要写进正文的事实。

#### ① 必须全量反编译，不要只看一个类

模组的行为经常不在你以为的那个类里：

| 你以为在 | 实际常在 |
|---|---|
| `XxxItem` | `XxxEatProcedure` / 事件监听器 / mixin |
| `XxxBlock` | `XxxBlockEntity` / `loot_tables/blocks/*.json` |
| 代码 | `assets/*/lang`、`models/`、`recipes/`、`blockstates/` |

所以流程固定是：**整个 jar 全量反编译 → 全仓库 grep → 再细读命中的类**。

```powershell
java -jar cfr.jar 模组.jar --outputdir 输出目录 --silent true
# 然后全仓库搜，不是搜单个文件
Get-ChildItem 输出目录 -Recurse -Filter *.java | Select-String -Pattern '"item_id"'
```

#### ② 一个结论要两条独立证据链

单一来源不下结论。可用的组合：

```
代码参数  +  资源文件（lang / 模型 / 战利品表）
全量 grep +  单个类细读
mojang 映射 + forge 映射（两份交叉对 SRG 名）
```

**失败案例**：SRG 名 `f_196xx_` 如果只查一份映射表就下结论，
一旦偏移一位，「夜视」会被写成「隐身」。必须 client.txt 与 joined.tsrg 两边对上。

#### ③ 第一遍产物不可信，包括自己上一轮写的

交付前回头核一遍。真实案例：

| 案例 | 第一遍结论 | 复核后 |
|---|---|---|
| 苹果箱 | 「纯装饰，不具备存储功能」 | 查 `loot_tables/blocks/apple_crate.json`：破坏掉 8 个苹果，箱体不返还 —— **定位整个错了** |
| 动物谷猫狗表格 | 品种表第二列只有部分行有值 | 逐行核对后补齐（20 行「宠物商人」+ 3 行「自然生成」） |
| Golden Carrot Juice | 饥饿值 1 | 用户质疑 → 回查 `super(1, 0.0f)` 确认是 1 —— 结论对，但**必须能翻出证据** |

#### ④ 每个数字都要能指到来源

| 写进正文的内容 | 必须来自 |
|---|---|
| 饥饿值 / 饱和度 | `FoodProperties` 构造参数（注意实际饱和度 = nutrition × modifier × 2）|
| 药水效果的等级与时长 | `MobEffectInstance(effect, ticks, amplifier)` |
| 掉落物与数量 | `loot_tables/**/*.json` |
| 生命值 / 护甲 | 属性注册（`Attributes.MAX_HEALTH` 等）|
| 注册名 / 名称 | `item.x` / `block.x` 的 lang 键 |
| 配方 | `data/*/recipes/*.json` 的 pattern / key |

**说不出来源的数字不要写**。宁可留空标「待确认」。

#### ⑤ 交付前五问

```
□ 整个 jar 都反编译了吗（不是只反了几个类）？
□ 这个结论有几条独立证据？
□ 每个数字能指到具体哪一行代码 / 哪个 json？
□ 上一轮的结论复核过吗？
□ 有没有「查了一处就下全局结论」的地方？
```

### 6.10.2 有前置就一起反编译

#### 为什么

模组的核心机制**经常不在它自己的 jar 里**。

| 情况 | 机制实际在哪 |
|---|---|
| 附属模组 | 前置本体（好感度/驯养/属性系统都在主模组）|
| 生物/方块扩展 | 前置本体定义了实体与注册表 |
| 兼容联动 | 被联动的那个模组提供接口 |

**只反扩展，会得出「本模组没有实现这套逻辑」的错误结论**，
或者把前置提供的能力写成「本模组提供」。

#### 步骤

**① 读依赖声明，拿到 modId 与版本范围**

```
Forge / NeoForge : META-INF/mods.toml
                   [[dependencies.<modid>]] 里的 modId / versionRange / mandatory
Fabric           : fabric.mod.json
                   depends / recommends
```

**② 按 modId 找下载（Modrinth 优先）**

```powershell
# Modrinth：开放 API，直链无防盗链
Invoke-RestMethod "https://api.modrinth.com/v2/project/<slug>/version"
# 取 [0].files[0].url
```

```
CurseForge：有防盗链，需要代理
  页面  https://www.curseforge.com/minecraft/mc-mods/<slug>/files
  直链  https://mediafilez.forgecdn.net/files/<id//1000>/<id%1000>/<filename>
  或查  https://api.cfwidget.com/minecraft/mc-mods/<slug>
```

**③ 版本必须对得上**

前置的 MC 版本与 loader 要和模组本身一致（看 `mods.toml` 的 `versionRange`）。
不匹配的前置反出来是另一套代码，结论照样错。

**④ 一起解包，同级目录，跨目录检索**

```
jar-analyze/<模组>/
jar-analyze/<模组>-前置1/
jar-analyze/<模组>-前置2/

# 检索时两个目录一起搜
Get-ChildItem <模组>*,<前置>* -Recurse -Filter *.java | Select-String -Pattern '"item_id"'
```

#### 坑

| 坑 | 说明 |
|---|---|
| **传递依赖** | 前置的前置也算（如某 API 又依赖另一个库）|
| **纯 API 前置** | Curios / Patchouli 这类只需看接口签名，收益低但要确认 |
| **版本漂移** | 不同前置版本行为不同，**必须记下确切的版本号**，写进交付说明 |
| **CF 直链防盗链** | 直接 `Invoke-WebRequest` 可能 403，需要 Referer 或走代理；Modrinth 没这问题 |

#### 判定：什么时候必须写「沿用」

如果正文要写某个机制，而这个机制的方法调用落在前置 jar 里：

```
✗ 本模组提供好感度系统，可以培养亲密度
✓ 好感度与驯养沿用 NFF: Girls 本体的体系，本模组只做生物扩展
```

**写错方向比写少更严重**——会把前置的功劳算在扩展头上。
