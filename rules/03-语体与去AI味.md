### 文风标准：生成时就写对（别写完再"去 AI 味"）

**目标文风一句话**：像维基的资深编辑写的技术条目——**平实、克制、信息密度高，可读但不聊天**。
既不是营销文案，也不是聊天记录；既不能有 AI 腔，也不能为了接地气而口语化。

#### 一、落笔就守的四条

| 要求 | 具体做法 | 反面 |
|---|---|---|
| **每句都带信息** | 首句直接给结论；条件、数值、效果写在同一句里 | 「值得注意的是，这个功能非常实用」——零信息 |
| **一段一件事** | 一段 2–4 句，只讲一个机制或一个限制 | 一段里混讲获取方式、效果、版本变更 |
| **量化优先** | 能写数字就不写形容：`30 秒冷却`、`4 点生命`、`220 tick` | 「冷却比较长」「血量很低时」 |
| **术语一手** | 用源码 / lang 文件里的名字，首次出现给全称 | 把「恒久遥远的理想乡」写成「那个回血 buff」 |

#### 二、生成时就要避开的 AI 腔（写的时候别写出来）

- **三连排比**：「既能…又能…还能…」「不只是…而是…更…」
- **升华收尾**：每段最后来一句总结或感慨
- **空转开头**：「随着…的发展」「作为一款…的模组」「在这个模组中」
- **套话连接**：「值得注意的是」「总而言之」「从某种角度来说」「在…方面」
- **形容词堆叠**：「丰富的内容、精美的界面、流畅的体验」
- **假客观**：「可以说」「不难发现」「众所周知」
- **每句等长**：连续 5 句都在 20–30 字，读起来像机器

#### 三、同时要避开的"过度口语"（这是另一个极端）

- **语气词**：吧、嘛、呗、啊、呀、哈
- **口头禅**：其实、说白了、基本上、反正、贼、挺、超级
- **玩梗/调侃**：出现在资料页正文里一律不合格
- **反问与感叹**：「是不是很实用呢？」「太好用了！」
- **括注过度**：一段里两个以上「（…）」插入语
- **把数值换成模糊说法**：「一大堆」「好几种」「挺久的」

#### 四、可读性下限（不能让人读得难受）

| 指标 | 上限 / 做法 |
|---|---|
| 单句字数 | 超过 **40 字**就要拆句；长定语套叠尤其要拆 |
| 段落句数 | **2–4 句**；超过 5 句拆段 |
| 连续同结构 | 连续 3 句同样句式（都是「…时，会…」）就换句式或合并 |
| 名词连缀 | 「崩坏能抑制剂合成配方解锁条件」这类 3 个以上名词叠加，改成短句分述 |
| 生词密度 | 首次出现的机制名给一句解释，或链到已有页面 |
| 列表 vs 段落 | 并列的条件、数值、步骤用列表/表格；因果与原理用段落 |

#### 五、按页面类型的字数基线（防灌水，也防太干）

| 页面 | 正文基线 | 说明 |
|---|---|---|
| 物品 / 方块 | 60–200 字 | 只写功能、获取、数值；没有内容不硬写 |
| 实体 / 生物 | 150–400 字 | 行为、掉落、应对方式 |
| BUFF / 状态 | 40–120 字 | 效果、数值、来源、持续时间 |
| 模组介绍 | 400–1200 字 | 概述 + 玩法 + 兼容；不写环境要求 |
| 教程 | 按步骤 | 每步一句动作 + 一句预期结果 |

#### 六、写完之后的自检（三轮，顺序不能换）

1. **事实轮**：数值、术语、条件、路径与来源逐条核对；
2. **AI 腔轮**：扫上表第二节的关键词，命中就删；检查句长是否过于均匀；
3. **口语轮**：扫上表第三节的词，命中就删；资料页要求 0 处。

> **判定口径**：读起来"平"是对的，"顺"也是对的，"俏皮"就过头了。
> 一段话里如果有一句让你觉得"这个说法有点可爱"，在资料页就删掉它。

### 去 AI 味：**只许删，不许加**（百科严谨性铁律）

> 这一节曾被误用成"把所有稿子口语化"，产出过为了口语而口语、削弱百科严谨性的稿子。
> 因此本节以三条铁律开头，**违反任何一条都算改坏**，宁可原样不动。

**铁律一：默认不启用**
只有用户明确说「去 AI 味 / 太像 AI / 太生硬」时才执行本节。用户没提，就保持原本的书面、严谨写法，**不要**主动"润色"成口语。

**铁律二：只删不加**
执行时删除的是**修辞**：总结句、排比、升华句、模板化结尾、空洞形容词、无信息的过渡句。
**禁止新增**：口语词（嘛、呗、说白了、其实）、语气助词、括号插入语、感叹句、反问句、主观评价。
判断标准：改完后的字数应当**持平或减少**；如果变长了，几乎一定是加了不该加的东西。

**铁律三：事实优先级高于文风**
下列内容**一个字都不许改、不许删、不许换说法**：

| 类别 | 例子 |
|---|---|
| 术语与机制名 | 「少女祈祷中……」「恒久遥远的理想乡」「休闲膝枕」必须与源码/lang 一致 |
| 数值与单位 | 30 秒冷却、4 点生命、20 tick、220 t、16 格 |
| 触发条件与限制 | 「生命降到 4 点以下」「每名女仆每天 1 次」「10 秒内连亲三次」 |
| 版本号 / 路径 / 指令 | `1.7.5.2`、`config/meow_machine_mystery.json`、`/meow reviewers` |
| 来源与依据 | 「依据 tags/items 定义」这类可核查说明 |

删改前先自问：**删掉这句之后，读者还能不能准确复述这个机制？** 不能，就说明删过头了。

#### 可以删 ⇄ 绝不能动

| 可以删（纯修辞） | 绝不能动（信息） |
|---|---|
| 每节末尾的总结/升华句 | 任何数值、时间、概率、倍率 |
| 「不是 A，而是 B」式自我澄清 | 触发条件、前置要求、例外、限制 |
| 模板化结尾（「以上内容基于 X 版本」） | 术语、机制名、物品/状态名 |
| 对仗短语、四字并列（「无需配置，随时可用」） | 配置路径、指令名、版本号 |
| 名词化空转（「自行决定重心」→「决定用哪一种」） | 结构：标题层级、`[hN=]`、`[ban:]`、表格 `th` |

#### 口语用量上限（按页面类型，超过即视为"为口语而口语"）

| 页面类型 | 口语词/插入语上限 | 说明 |
|---|---|---|
| 资料页（物品 / 方块 / 实体 / 生物 / BUFF） | **0 处** | 只写功能与数值，不评价、不调侃 |
| 教程页 | 最多 2 处 | 且不得影响步骤复现 |
| 模组介绍页 | 每 500 字最多 1 处 | 允许一次主观建议，如「十分建议启用」 |

#### 术语禁止改写成俚语

| 正确（保留） | 改坏的样子（禁止） |
|---|---|
| 好感本身有 30 秒的获取冷却 | 好感有个三十秒冷却吧，反正刷不快 |
| 每名女仆每天只有 1 次机会 | 一天就一回，别想多 |
| 按完整 35 条编辑规范读稿 | 照着 35 条规矩挑刺 |
| 生命降到 4 点以下时触发 | 血掉到四颗心就来了 |

#### 改坏的真实例子（别重复）

| 原句（严谨） | 被改坏 | 坏在哪 |
|---|---|---|
| 生命降到 4 点以下时触发 | 血掉到四颗心就来了 | 「4 点」变成模糊的「四颗心」，触发条件丢失 |
| 每名女仆每天只有 1 次机会 | 一天就一回，别想多 | 删掉了"每名女仆"这个作用域 |
| 按键映射为 `key.touhou_maid_affection.kiss` | 按键就是那个亲亲键 | 本地化键名被删，读者无法核对 |
| 梗图共 23 张 | 梗图挺多的 | 数量信息丢失 |

#### 执行顺序：先严谨，后文风

1. 第一遍：只核对事实（数值、术语、条件、路径、来源），**不做任何改写**；
2. 第二遍：做纯修辞清理（只删不加）；
3. 第三遍：按上限检查口语用量，超出就继续删。
反过来的顺序会先删掉事实，无法回补。

#### 交付前自检（逐条打勾，缺一不可）

- [ ] 所有数值 / 单位 / 条件 / 路径与原文逐条对照，无一处变化
- [ ] 术语与源码或 lang 文件一致，没有"通俗化"替换
- [ ] 新增的口语词 / 插入语数量未超上限，且没有「嘛 / 呗 / 说白了 / 其实」
- [ ] 没有把陈述句改成反问句、感叹句、玩梗句
- [ ] 标题层级、`[hN=]`、`[ban:]`、表格 `th` 结构完全未变
- [ ] 总字数持平或减少（变长＝可能加了修辞）
- [ ] 找不玩这个模组的人读一遍，他能说出关键数值与触发条件

**判断标准（原来的那一句要反过来用）**：念一段稿子，如果**信息全、数值准、句子长短不一**，就是合格；
不是"每句都短、都有语气词"才叫自然。

**顺带说一个功能**：Mcmodder 的**吐槽**会在正文里写成
`<span class="uknowtoomuch">…</span>`（设置项「匿名吐槽」控制是否记录创建人）。
这是**刻意的趣味写法**，页面渲染成悬浮才显示的效果；作者主动加时就保留，
不要当成脏标签删掉。只有"从别的稿子复制粘贴带进来的意外残留"才需要清理。

### 6.2.2.2 「去 AI 味」不是「口语化」——正文语体标尺

去 AI 味有两个失败方向，**都已踩过至少一次**。

```
← 口语化（矫枉过正，错）
   "地牢是一层一层往下叠的"
   "吃下去给两分钟夜视"

← 中心点：百科规范书面语
   "地牢由多层叠加构成"
   "食用后获得 120 秒夜视"

→ AI 套话（原始问题，也错）
   "值得注意的是，这个模组不仅仅……而且还……"
```

百科要的是**第三种语体**：准确、简洁、不带语气，但也不端着。既不能像聊天，也不能像产品文案。

### 高频口语 → 规范对照

| 口语 | 规范 |
|---|---|
| 组 / 两两组合 | 组合 |
| 做 / 做出 / 做成 | 制作 / 制成 |
| 给 | 提供 / 获得 |
| 加了一层 | 增加了一层 |
| 强 / 都强 | 高于 |
| 开工 | 开展 |
| 用不上 | 作用有限 |
| 边跑边吃 | 在移动中进食 |
| 那几样 | 该系列 |
| 嗑一颗 | 食用 |
| 摸黑赶路 | 继续探索 |
| 挖进去 | 挖掘进入 |
| 自己长在地下 | 在地下自动生成 |
| 刷什么怪 | 生成的生物组合 |
| 亏本 | 净亏损 |
| 挂在（某个地点）| 绑定在 |
| 常改的是 | 常用的配置如下 |

### 该删 / 不该删

去 AI 味时容易连带删掉正常内容，这是第二次踩的坑。判断标准：

| 该删 | 不该删 |
|---|---|
| 「真正能逛的」「更难受」这类**评价** | 「大房间做高会空」这类**因果解释** |
| 「这是它的实际含义」这类**解释尾巴** | 「按族系分成这几类」这类**过渡句** |
| 「值得注意的是」这类**套话** | 具体**数字与机制** |
| 「不得不说」「显而易见」这类**语气词** | 名词性的**专业表述** |

删掉的应当是「作者的态度」，不是「作者知道的事」。

### 自查清单

改完正文后逐条过：

1. 有没有「就 / 都 / 挺 / 蛮 / 吧 / 呢」这类语气词？
2. 动词是不是口语化的（搞、弄、做、给、弄成）？
3. 有没有替玩家描述主观感受（「进去不至于只有四面墙可看」）？
4. 反过来：有没有砍掉因果关系，只剩干巴巴的结论？
5. 句长中位是不是掉到了 20 字以下？（掉太低通常是砍过头了）
6. 有没有「值得注意的是 / 不仅…而且 / 无疑 / 某种程度上」？

前三条是口语化，后三条是 AI 味，中间是标准。

### 10.2.1 7B 模型救不了「对比句式」——这是结构性 AI 味

实测（2026-11-11，CDS 战利品表页 424 字）：

```
输入：箱子里出现什么，不是随机撒的，而是由战利品表决定…
7B SFT 输出：箱子里出现什么，不是随机撒的，而是由战利品表决定…   ← 一字未改
信息保留率 100%，AI 味评分仍是 100
```

**原因**：SFT 的训练目标是「删套话词」（值得注意的是、综上所述、不仅…而且），
而「不是 X，而是 Y」是**句式结构**，不是词。词表检测器也抓不到——它查的是词，不是句法。

#### 这类结构自己要抓

| 结构 | 例子 | 问题 |
|---|---|---|
| **不是 X，而是 Y** | 不是随机撒的，而是由战利品表决定 | 用否定垫背来强调，AI 最典型的说理腔 |
| **是 X，不是 Y** | 「战利品」是方块，不是掉落物 | 同上，反过来说 |
| **而不是…** | 答案在表里，而不是在代码里 | 制造一个读者没在想过的对立面 |
| **并非…而是…** | 同第一行 | 更书面，但结构一样 |
| **并不 X，而是 Y** | 并不将灭绝生物直接投入世界生成，而是设计了复活流程 | 同一个家族，动词换成「并不」也还是它 |
| **不是简单的 X** | 装罐不是简单的容器替换 | 连「而是」都省了，仍然预设了一个错误认知 |
| **所以…（承接设问）** | 所以「能开出什么」这类问题… | 自问自答的论文腔 |

#### 改法：直接陈述，删掉否定垫背

```
✗ 箱子里出现什么，不是随机撒的，而是由战利品表决定。
     所以「民用战利品里能开出什么」，答案都在表里，而不是在方块的代码里。

✓ 箱子里出现什么，由战利品表决定：每种战利品方块各绑定一张表，开箱时从该表里抽取。
     要查某种箱子的产出，看它对应的表即可。
```

```
✗ 本模组里的「战利品」是方块，不是掉落物。

✓ 本模组里的「战利品」指方块——民用战利品、军用战利品这些名字对应的都是一种箱子。
```

#### 实测漏网：检测器 100 分，人一眼看出来

三页连续踩同一个结构，`ai-tell-check.py` **全部给 100 分**：

| 页面 | 原文 | 变体 |
|---|---|---|
| Canned Food and Drinks 14363 | 装罐不是简单的容器替换：每件罐装食品沿用原版数值… | 不是简单的 X |
| Tax' Village Architect 15221 | 村庄并非分散的房屋，而是一组由玻璃穹顶连成的建筑群。 | 并非 X，而是 Y |
| De-Extinction 12157 | 该模组并不将灭绝生物直接投入世界生成，而是设计了一条完整的复活流程。 | 并不 X，而是 Y |

改法都一样——删掉否定垫背，直接说正面：

```
✗ 装罐不是简单的容器替换：每件罐装食品沿用原版数值，只是换了个包装。
✓ 罐装食品沿用原版食物本身的饥饿值与饱和度，只是换了个包装。

✗ 村庄并非分散的房屋，而是一组由玻璃穹顶连成的建筑群。
✓ 村庄是一组由玻璃穹顶连成的建筑群，没有分散的独立房屋。

✗ 该模组并不将灭绝生物直接投入世界生成，而是设计了一条完整的复活流程。
✓ 该模组设计了一条完整的复活流程，灭绝生物不会直接出现在世界生成中。
```

**手动扫描用**：

```powershell
# 把这几个词在草稿里过一遍，命中就人工判断
Select-String -Path 草稿.html -Pattern "并非|而非|而不是|不是.{1,20}而是|并不.{1,25}而是|不是简单的"
```

**判断口诀**：一句话里出现「不是 / 而不是 / 并非 / 并不」，先问「读者是否真的会在意那个否定项」。
不在意就删——留着的往往是给强调找理由，不是信息。

#### 检查脚本

```python
import re

PATTERNS = [
    (r"不是[^，。]{1,12}，而是", "不是X，而是Y"),
    (r"是[^，。]{1,10}，不是[^，。]{1,12}", "是X，不是Y"),
    (r"而不是[^，。]{1,20}", "而不是…"),
    (r"并非[^，。]{1,12}，", "并非…"),
]
for pat, name in PATTERNS:
    for m in re.finditer(pat, text):
        print(f"[{name}] …{text[max(0, m.start() - 20):m.end() + 20]}…")
```

### 10.2.2 「内容太碎」+ AI 味的实测清单（2026-11-13，三篇连退）

三篇被同一句话退回：**内容太碎了，AI 味严重**。拆开看是两件事——
**碎**是结构问题（分节多、并列多、参数密），**AI 味**是句式问题。

#### 一、对比句式（这次是三处，且都是新变体）

| 原文 | 变体 | 改法 |
|---|---|---|
| 玩家面对的**不再是**原版的自然地形，**而是**一条首尾相接、可以自行重排的维度链 | 不再是 X，而是 Y | 主世界与下界被换成分层平地，末地保留岛屿轮廓，三者首尾相接，可自行重排 |
| 后者的引信燃尽时播的是玄武岩三角洲的环境音，**不是**爆炸声 | 是 A，不是 B | 引信燃尽时播放玄武岩三角洲的环境音 |
| 让收件人在拆包、开箱或伸手去摸邮筒的那一刻，**替寄件人完成最后一步** | 叙事化收尾（无否定词，但同一副腔调）| 整段删掉，只留机制 |

**第二处尤其值得记**：它没有「不是X而是Y」的完整骨架，只有一个尾巴「不是爆炸声」。
检测器抓不到，人一读就知道在纠正一个没人提出的误解。

#### 二、六类高频句式（按出现密度排）

| 类型 | 原文摘录 | 问题 |
|---|---|---|
| **冒号总括 + 对仗** | 全部围绕同一件事：同一种炸药，不同的引爆方式与威力 | 先给一个空抽象，再对仗展开 |
| **抽象总括** | 整套内容不提供配置项，引信长度、爆炸威力、投掷冷却都是固定值 | 「整套内容」这类主语没有信息 |
| **评价性判断** | 与普通物品区分明显 / 基本没有躲避余地 / 是纯粹的空中场地 / 缺一不可 / 四面等价 / 它能只认踩踏 / 只能等它炸 / 把竖直方向整段掀开 | 百科写事实，不写观感 |
| **"算是"式定位** | 算是这条支线的完成标志 | 给物品安一个意义 |
| **免责式结尾** | 缺少对应模组时…其余内容不受影响 / 装进整合包不会和其他模组争配置 | 三篇全用同一招收尾 |
| **代码腔** | 不注册任何行为目标 / 标为防火 / 硬度被设成极大值 | 翻译成玩家语言 |

#### 三、免责式结尾为什么扎眼

三篇的最后一段都是「不依赖 / 不受影响 / 不会争配置」：

```
✗ 模组不依赖其他模组，缺少兼容模组时主要玩法不受影响。
   （而且和前一句「检测到快递模组时两种陷阱会额外注册拆包效果」自相矛盾）

✓ 兼容部分只在前置一节写一句：检测到 cmpackagecouriers 时，
  陷阱物品额外注册拆包效果；未安装则无此项。
```

**规则**：兼容信息写在「前置与兼容」节里就够了，不要在文末再加一句总结。

#### 四、「碎」的三个量化特征

这批正文每篇 800~1100 字，却分成 5~6 个 h2，每节 100~200 字。症状：

| 症状 | 实例 | 处理 |
|---|---|---|
| **一节一件事，节数过多** | TNT 那篇：触发路径 / 威力梯度 / 安装形态 / 钻地与实验 / 兼容 | 合并同类：触发方式合成一节，威力并进各形态 |
| **一句话多个并列** | 方块里有两级强化 TNT、装成按钮的薄片炸药、压成压力板的贴地 TNT、向下连爆的钻地型，以及一枚分十段递增的实验方块 | 拆成表格 |
| **参数密度过高** | 初速 1.5，散布很小…每次投掷后进入 30 刻（1.5 秒）冷却 | 只留玩家能感知的，代码里的中间值删掉 |

#### 五、参数取舍：只写玩家能感知的

```
✗ 碰撞体积 0.5 格，标为防火…引信 60 刻（3 秒），威力 3.0
      （碰撞体积、实体标签这些是代码内部量，玩家感觉不到）

✓ 引信 3 秒，爆炸威力略高于原版 TNT，不产生火焰
      （保留：引信时间、相对威力、有没有火）
```

**判据**：这个数字玩家能不能直接感觉到？感觉不到就不写。
同类的中间量还有：初速、散布角、堆叠上限（除非异常）、冷却刻数（换算成秒可留）、
实体标签、注册行为目标。

#### 六、审核点名的数值格式

> 还有数值部分需要用阿拉伯数字（"一万点生命" → `[icon:health=10000,点]`）

生命值、护甲、攻击伤害这类**属性数值一律用 `[icon:...]` 标记**，不要写成中文数字：

```
✗ 实体带一万点生命
✓ 实体生命值 [icon:health=10000,点]
```


### 10.2.3 AIGC 痕迹八条判据（审核判「严重」的真实案例）

**案例**：动物谷：猫猫狗狗（3863）的模组页。审核判「严重 AIGC 痕迹」。
后来有人改了一版，实质差异只有三处错别字：

```
animal谷本体 → 动物谷本体
向购买取得   → 向他购买取得
小鸡         → 鸡
```

**句式、段落模板、表格排布一字未动，审核照样判严重。**
说明审核看的是句法与段落结构。**改错别字不算改。**

#### ① 段落结构同构（最致命）

```
品种          → 一句总述 + 表格 + 一句补充
行为与驯服     → 一句总述 + 三条要点 + 一句补充
饲养与装饰方块  → 一句总述 + 表格 + 一句补充
宠物商人      → 一句总述 + 一句补充
```

四节用同一个「总述 → 列举 → 补充」模具。人写百科节奏是乱的：
有的节一句话就够，有的节要展开。**整齐得像模板，就是最硬的指纹。**

#### ② 补齐型对仗（「不 X，而 Y」的四个变体）

| 原文 | 变体 |
|---|---|
| 它**不引入**新的驯养系统，**沿用**动物谷本体的喂食与驯服机制 | 不引入 X，沿用 Y |
| 攻击**只针对**动物，**不针对**玩家 | 只针对 X，不针对 Y |
| 猫与犬科**共用**一套行为框架，**区别只在**攻击目标 | 共用 X，区别只在 Y |
| **其中**宠物碗与几处睡床有实际作用，**其余只作**装饰 | 其中 X 有用，其余 Y |

一句话里同时出现肯定与否定两个半句，就是同一个语法模具。
和 §10.2.1 的「不是 X 而是 Y」是同族，只是把「不是」换成了「不引入 / 只针对 / 共用 / 其中」。

#### ③ 「除了…还…」递进

> **除了动物**，模组**还加入了** 7 种饲养与装饰方块，**以及**一个专门卖猫狗的宠物商人村民。

三项并列 + 递进连接词，一句话塞完所有新增内容。

#### ④ 完整性宣言

> 此模组把猫和狗**做成了完整的一套**
> 8 个猫品种、15 个犬科品种，**每个品种都有**成年公、成年母与幼崽三种形态

用「完整」「每个都…」证明覆盖面，而不是陈述事实。

#### ⑤ 比喻化收尾（这次校正的）

> 狗跟着玩家走时，羊也会跟着狗，**等于一个会自己走路的赶羊器**。

以前把它当「像人写的好句子」，实际上**它也是 AIGC 特征**：
机制已经说清楚（狗走、羊跟）了，多出来的比喻是**为了好听而加的**。
跟「替寄件人完成最后一步」同一类。

#### ⑥ 最高级强调

> **德国牧羊犬**是**唯一的特例**

「唯一」「最」「典型」这类最高级，是给事实加价值判断。

#### ⑦ 表格同一列几乎全同

品种表第二列 20 行写「宠物商人」，只有 3 行是「自然生成」。
人一般会合并成一句话（「除豹猫、狼、狐狸外均需购买」）或改列结构。

#### ⑧ 版本信息节

```
版本信息
当前版本 1.0.0.28，对应 Minecraft 1.12.2。前置为动物谷:基本（Animania）。
```

违反 §6.2.2.3；前置信息应该进「前置」节。

#### 改法示范

```
✗ 它不引入新的驯养系统，沿用动物谷本体的喂食与驯服机制。
✓ 驯养沿用动物谷本体的喂食与驯服机制。

✗ 猫与犬科共用一套行为框架，区别只在攻击目标。
✓ 两者的行为逻辑相同，攻击目标不同：猫打小型动物，犬科打山羊、绵羊与兔子。

✗ 狗跟着玩家走时，羊也会跟着狗，等于一个会自己走路的赶羊器。
✓ 狗移动时，附近的羊与山羊会跟着它一起走。
```

**规律**：删掉补齐的后半句，句子更短，信息一条没少。
那些「不 X 而 Y」的补语，读者并不需要。

#### 自检清单

```
□ 四节以上的页面，各节的段落形状是否一样？
□ 有没有「不X而Y / 只X不Y / 共用X区别在Y / 其中X其余Y」？
□ 有没有「除了…还…以及…」一句三并列？
□ 有没有「完整的一套 / 每个都 / 唯一 / 最」这类价值判断？
□ 有没有为了好听加的比喻？
□ 有没有一列全是同一个值的表格？
```
