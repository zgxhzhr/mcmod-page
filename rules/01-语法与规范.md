## 2 百科正文能吃什么

### 2.0 方括号标记：必需标签，一个都不许删

| 标记 | 作用 | 能删吗 |
|---|---|---|
| `[h1=…]` … `[h6=…]` | 标题，同时决定目录层级 | ❌ |
| `[ban:…]` / `[mark:…]` / `[hide:…]` / `[nocat:…]` | 页面级指令（标题栏、隐藏内容、分类控制） | ❌ |
| `[icon:health=20,点]` | 血量等图标 | ❌ |

它们**不是** Markdown 残留，也不是转义噪声或"旧格式"——是百科认的标签，删了页面就掉标题、掉图标、掉指令。

- 见到就**原样搬**：连同它所在的 `<p>`（或裸文本位置）一起复制过去。
- **不许"为了干净"删掉**，也不许把 `[h1=概述]` 当"冗余根节点"删——那是正文第一节的标题（§2.3 / §2.4）。
- 要改任何 `[hN=]`（改文字 / 删 / 升降级）＝结构性改动，先问用户。

**怎么区分标签和普通方括号**：`[关键字=…]` 或 `[关键字:…]`（带等号/冒号）才是标签。正文里长得像方括号的普通文字——`[未同意导出]`、`[玩家名]家的水壶响了`——是原文，不是标签，照常编辑、改写、翻译，别让这条规则把它们也锁住。
### 2.1 标签对照

| 要表达的 | 唯一正确写法 | 备注 |
|---|---|---|
| 标题 | `<p>[h1=标题]</p>` … `[h6=]` | 正文里是纯文本标记，渲染时才变标题；编辑器里看到 `[h3=…]` 是正常的 |
| 段落 | `<p>…</p>` | |
| 表格 | `<table><tbody><tr><th>表头</th>…</tr><tr><td valign="top"><p>…</p></td>…</tr></tbody></table>` | 表头**必须** `<th>`，见 §2.2 |
| 合并单元格 | `<td rowspan="4" valign="top">…</td>` | UEditor 通常保留；粘完点一次「正文预览」确认 |
| 列表 | `<ul class="list-paddingleft-2"><li><p>…</p></li></ul>` | **必须 `li > p`**；`ol` 用同一个 class；编辑器存回来会变成 `class=" list-paddingleft-2"`（多一个前导空格），不影响渲染 |
| 代码块 | `<pre class="brush:java;toolbar:false">…</pre>` | 要带语言（`brush:` 后面那段，如 `java` / `text` / `shell`）；不带语言编辑器会提示选择 |
| 血量图标 | `[icon:health=20,点]` | 后面**不要**再写"点"，会变成"20 点点血量" |
| 标题 / 菜单栏指令 | `[ban:title_menu]` 或 `[mark:title_menu]` | 两种写法都见过（本模组页用的是 `mark`）；**包在 `<p>` 里也能正常生效**，不要改原稿写法 |
| 图片 | `<img src="…" alt="…">` | 编辑器会自己补 `_src` |
| 文字颜色 | `<span style="color: rgb(255, 0, 0);">文字</span>` | 语法如此（`rgb(r, g, b)` 逗号后带空格、`;` 在引号内）；**默认一个字都不上色**，只有用户主动指定「哪段文字、什么颜色」时才加，见 §6 |

**不支持**（会导致红框或结构错乱）：`<code>` 行内代码、`<blockquote>`、`<hr>` / `---` / `* * *` / `===` 这类分割线（规范第 22 条明令禁止字符串或图片做的分割线）。

### 2.1.1 数值类属性用 `[icon:…]` 自适应图标组，不要手打文字

**审核会退回手打的「生命值 20 点」「饥饿值 4 点」。** 百科有一套「自适应图标组」，
给数值就会自动按游戏设定取整并画出对应数量的图标（支持小数）。

```html
[icon:health=5]         → 5 点生命值，自动画成 2.5 颗心
[icon:health=5,点]      → 「5点」+ 2.5 颗心图标
[icon:hunger-level=4,点] → 「4点」+ 饥饿值图标
```

第二个参数是「数值前面显示的单位文字」，不写就只显示图标。**写了单位就不要再在外面重复写「点」**，
否则会出现「20 点点生命值」。

#### 可用的图标名

| 图标名 | 对应属性 |
|---|---|
| `health` | 生命值（普通） |
| `health-ex` | 生命值（极限模式） |
| `hunger-level` | 饥饿值 |
| `saturation-level` | 饱和度 |
| `armor` | 盔甲值 |
| `toughness` | 盔甲韧性 |
| `health-buff-regeneration` | 伤害吸收 |
| `health-buff-poison` | 中毒 |
| `health-buff-wither` | 凋零 |
| `health-jockey` | 乘骑 |

### 2.2 表头样式：用 `<th>`，不要用 `<td class="firstRow">`

百科（UEditor）存回来的表头就是 `<th>`——这是它认可的形态。你给 `<td><p><strong>表头</strong></p></td>`，编辑器会把 `class="firstRow"` 丢掉、改写成 `<th>`，等于白写。

```html
<table style="width: 409px;">
  <tbody>
    <tr>
      <th style="word-break: break-all;">目录</th>
      <th style="word-break: break-all;">用途</th>
    </tr>
    <tr>
      <td valign="top"><p><strong>maid_file/maid_exports/</strong></p></td>
      <td valign="top"><p>导出结果，按玩家名分子文件夹。</p></td>
    </tr>
  </tbody>
</table>
```

| 项 | 正确 | 错误 |
|---|---|---|
| 表头单元格 | `<th>表头</th>`（纯文本，推荐；转换器给的就是这个） | `<td valign="top"><p><strong>表头</strong></p></td>` |
| 另一种合法形态 | 编辑器自己插表时存成 `<thead><tr><th valign="top"><p><strong>表头</strong></p></th></tr></thead>`，同样被原样保存、正常渲染 | 同一页里别混用两种；`<th>` 内部包 `<p>`/`<strong>` 不算错 |
| 表头行 | `<tr>` | `<tr class="firstRow">` |
| 数据单元格 | `<td valign="top"><p>内容</p></td>`（内容仍要包 `<p>`） | `<td>内容</td>` |
| 名称列强调 | `<td valign="top"><p><strong>名称</strong></p></td>` | 把名称做成 `<th>`（那是表头） |
| `style="width: …"`、`word-break`、图片 `_src` | 编辑器自动补，不必手写 | 手写 |

`scripts/md2mcmod.py` 与 `scripts/rowspan.py` 已按此输出 `<th>`。

### 2.3 标题序号：跟着原文走，别自己加

**序号一律以原文为准**：

- 原文标题带 `Ⅰ.` / `1.` / `一、` → **原样保留**，连样式都不改（`Ⅰ.` 就不要改成 `1.`）。
- 原文标题**没有**序号 → **不要加**。目录本来就自动编号，不需要人手补。

**只有「原文有序号 ＋ 页面有目录」时才需要问一句**，因为这时才会出现双层编号（目录自动编号 `1.1` + 标题自带 `Ⅰ.`）：

| 情况 | 处理 |
|---|---|
| 原文有序号，页面有目录 | 问一句：「目录会自动编号，标题里的 `Ⅰ.` 会显示成 `1.1 Ⅰ. …`，保留还是去掉？」 |
| 原文有序号，页面**没有**目录（纯段落/表格页） | 不问，原样保留 |
| 原文**没有**序号 | 不问，也不要加 |

几条容易搞反的：

- 用户答「**保留**」＝ **别去动它**，不是"给它补上"。原文本来没有序号时更要小心——先反问一句「保留＝保持原样、我不改动，对吗？」再动手。
- 用户答「**去掉**」才删，且**只删这一页**的，别顺手改别的页面。
- 现有页面只是**样例**，不是模板。某页写了 `Ⅰ.` 不代表别的页也要写；某页有目录不代表每页都要建目录。
### 2.4 改动边界：只加不删

被要求「加一节」「加一段」「加个目录项」时：

- **只新增**：新的 `[hN=]` + 新的表格/段落，插到内容该在的位置。已有内容一个字不动。
- **已有的 `[hN=]` 标题一律不动**——不改文字、不删、不随便升降级。尤其是 `[h1=概述]` 这类正文首节：删了它，这一节就没有标题了，内容会并进页面顶部，属于肉眼可见的破坏。
- **删除 / 合并 / 降级任何已有标题、删除任何已有段落**＝结构性改动：先说明后果、**拿到明确同意再做**。不要为了"目录好看""编号整齐"顺手改别人已发布的结构。
- 新增的章节层级要贴着上下文选：插在 `[h2=]` 之间就用 `[h2=]`，别为了区分而跳级。
## 3 编辑规范（审核口径，引用请用条号）

报告里写"违反第 12 条"比写"标点不规范"有用——审核意见也是按条号给的。

### 3.1 公共编辑内容通用规范（35 条）

| 条 | 不允许 |
|---|---|
| 1 | 主观词句（"我觉得""个人认为""并无卵用"、非客观强度对比、"小编/笔者"等第一人称） |
| 2 | 不确定语句（"也不太清楚""貌似""据说"）；**例外**：墨菲定律式概率可写"可能会引发崩溃" |
| 3 | 不规范用语（"卡爆渣机""撸树""骚年""鬼畜"）、颜文字、表情图、无帮助的 **emoji** |
| 4 | 不文明用语 |
| 5 | 与制作团队无关的个人署名（"由 XXX 汉化"） |
| 6 | 错别字、病句、语句不通顺 |
| 7 | 机翻、**AIGC**、明显翻译错误 |
| 8 | 与资料说明无关的内容；少量吐槽必须用工具栏**「吐槽」功能遮住**（作者原话例外） |
| 9 | 硬广型站外引导（只给链接不给介绍、"具体玩法请到 XX 查看"） |
| 10 | 误导内容、图文不符、重复内容 |
| 11 | 分区错误、资料类型/模组元素选错 |
| 12 | **标点缺失或误用**：句末缺句号、全半角不统一、用空格代替标点 |
| 13 | 防盗链/水印外站图片、404 链接 |
| 14 | 非教程类嵌入视频 |
| 15 | 只增删吐槽部分，或吐槽比例高于正常介绍 |
| 16 | 非授权转载 |
| 17 | 译名不符合主站通用命名规则 |
| 18 | 凑字数、内容不实、纯灌水 |
| 19 | 情绪化堆叠标点（"。。。""！！！""？？？"） |
| 20 | 不合授权协议就给第三方（如网盘）下载地址 |
| 21 | 空内容或毫无逻辑的字符 |
| 22 | **字符串或图片拼成的分割线** |
| 23 | **介绍不同版本特性必须写明具体 MOD/MC 版本号**，禁用"新版/旧版/老版本" |
| 24 | "PS."/"PSS."/"注"等前后缀；注解应融入正文 |
| 25 | 任何服务器宣传性质内容 |
| 26 | **排版不佳**：文字间过多换行/空格、过于鲜艳刺眼的文字颜色 |
| 27 | 内容被其他模组或材质包改到难以辨认 |
| 28 | 作者/开发组未公开宣传或发布的信息 |
| 29 | 冗余句（"欢迎各位补充""介绍就到这里""未完待续"） |
| 30 | 删掉正确内容；历史内容要保留并注明版本 |
| 31 | 打补丁式批改/删除线（有误就删，不能划掉再批改） |
| 32 | 无文字穿插时连续 6 张以上高度 >500px 的图片 |
| 33 | 同类资料文本重复率高却不使用「综合」/「引用」 |
| 34 | 同批次提交大量仅分类或名称变动（用后台批量功能） |
| 35 | **文中代码总长 >500 字节却没正确使用代码块工具** |

实战最常踩：**3（emoji）、12（标点）、18（内容不实）、22（分割线）、23（版本号）、26（颜色/排版）、35（代码块）**。

### 3.2 合成表（5 条）

不得删除历史合成表（要加"出现版本/移除版本"）、加重复合成表、不标需求版本或 MOD 需求、用新版直接替换老版（应保留历史并设"开始版本/结束版本"）、提交不存在的或私改的合成表。

### 3.3 教程（10 条）

不得：站外引导；以视频为主；只做单资料简介（应写进对应资料条目）；主题不明或分 Part（会被转为个人教程）；违反通用规范；服务器宣传；过于陈旧或烂大街；同主题重复建；以复制粘贴 `.lang` 为主；标题含无关内容/吐槽/装饰字符。

### 3.4 日志（自 2020-10-15 起）

必须保留原文；翻译按"一句原文一句译文"对照，或原文与译文上下分块。

### 3.5 新旧版本

**优先介绍新版本的用法，老版本保留并写在条目末尾、带上版本号。**

## 4 排版决策链（"观感差"怎么救）

用户说"观感还是那样"时，问题通常不是你换了容器，而是**页面没有抓手**。沿这条链往上走，停在对方点头的那一级：

| 级别 | 做法 | 什么时候够 |
|---|---|---|
| L0 | 一堆段落 | 永远不够 |
| L1 | 换成一张表格 | 只解决对齐，读者仍没抓手，**会被否** |
| L2 | 表格 + 一列"轴"（类型/倾向/阶段），按轴排序 | 条目 20 条以内通常够 |
| L3 | 按轴分组：每组一个 `[h2=]`/`[h3=]` + 一张小表 | 条目 30 条以上，或多维数据 |
| L4 | L3 + 首列 `rowspan` 合并 | 一个条目有多条子记录（如"性格 × 4 事件"） |

要点：

- **轴必须是数据自带的维度**（效果类型、正负向、阶段、时间点）。用"看起来像不像花"这种外部维度会被否。
- 轴定了就**跨页一致**，同类页面用同一套分组，否则口径会漂。
- **一条一格，别塞多句**；一格超过两句就拆列或拆表。
- 表头 `<th>`；**名称列用 `<strong>`**。
- 单表行数到 100+ 就拆成若干张 30 行表。
