## 5 工具

### 5.1 `scripts/md2mcmod.py` — Markdown → 百科 HTML

```bash
python scripts/md2mcmod.py 输入.md [-o 输出.mcmod.html] [--color-code] [--bold-first-col]
```

- `#`→`[hN=]`、表格（表头 `<th>`）、`ul/ol`→`list-paddingleft-2`、```` ```java ````→`<pre class="brush:java">`、`![alt](url)`→`<img>`、`[文字](url)`→`<a>`；
- `* * *` / `---`（分割线）直接丢弃；`[ban:…]`/`[mark:…]`/`[hide:…]` 之类指令输出为裸文本（包 `<p>` 也能生效）；
- 默认**不给行内代码上色**（合规优先）；`--color-code` 才用 `rgb(199,37,78)`；
- `--bold-first-col` 把每张表首列加粗（名称列）。

### 5.2 贴到哪：优先「源代码编辑器」

百科编辑页顶部有两个开关（装了 Mcmodder 就有）：

| 编辑器 | 吃什么 | 评价 |
|---|---|---|
| **源代码编辑器**（勾选） | 完整 HTML | ✅ **首选**。`[hN=]`、`<th>`、`rowspan`、`<pre class="brush:…">`、颜色都能原样生效 |
| Markdown 编辑器 | Markdown | 次选。表达不了合并单元格与颜色，转换还可能打红框 |

所以：**主交付物固定是 `.mcmod.html`**，Markdown 源稿作为附件（便于回改与追溯）；交付话术里必须写一句 **"粘之前先勾「源代码编辑器」"**。
### 5.3 `scripts/rowspan.py` — 首列合并

```bash
python scripts/rowspan.py 页面.mcmod.html [-o 输出.html]
```

源稿里**首列重复写**同一名称，跑一遍就会把相邻同名行合成一个 `rowspan` 单元格；含 `<th>` 的表头行不参与合并。

### 5.4 Mcmodder（浏览器油猴脚本，可选）

| 项 | 链接 |
|---|---|
| 仓库 | <https://github.com/Charcoal-Black/Mcmodder> |
| 直接装最新版 | <https://github.com/Charcoal-Black/Mcmodder/releases/latest/download/mcmodder.user.js> |

装法：篡改猴启用 → 同页打开「允许用户脚本」（不开则脚本能装但不执行）→ 打开上面的直链 → 点「安装」。

它能给编辑页加「源代码编辑器」「Markdown 编辑器」开关。**但不要用它转格式**：它的 Markdown→HTML 只告警不修正，遇到 `<code>`/`<blockquote>` 会打红框，而那些内联样式会随正文一起保存。用本技能的 `md2mcmod.py`。

### 5.4 `scripts/render-mc-model.py` — 按模型 JSON 渲染真实外观（最优先）

**当模组自带 `models/block/*.json` 时，用这个脚本，不要用四面平均色的近似渲染。**

它读方块的 elements / faces / uv，把每个面按纹理逐像素映射到等轴测投影上，
输出的是**游戏内实际外观**——复杂几何（机器、家具、多层结构）能完整还原。

```bash
python render-mc-model.py <模型引用> <资源根目录> <输出png> [尺寸]
```

模型引用两种写法：

```bash
# 1. 直接给模型路径
python render-mc-model.py "deextinction:block/block_dna_extractor" "mod;vanilla" out.png 128

# 2. 给方块 id，自动从 blockstates 找模型（推荐，模型常在子目录）
python render-mc-model.py "blockstate:deextinction:block_cleaning_table_white" "mod;vanilla" out.png 128
```

`资源根目录` 用分号分隔，前面的优先。要能解析 `assets/<ns>/textures/<path>.png`
和 `assets/<ns>/models/<path>.json`。

**原版资源从客户端 jar 里取**（模组模型常引用 `minecraft:block/iron_block` 这类原版贴图）：

```bash
# 本机客户端在 E:\PCL\.minecraft，版本目录里的那个大 jar 就是
tar -xf 1.20.1-Forge_47.4.28.jar -C <输出目录> "assets/minecraft/models" "assets/minecraft/textures"
```

解出来约 977 个方块纹理 + 2016 个模型，十几 MB，够用很久。
版本不同不影响方块贴图（iron_block 这类基础贴图多年未变）。

### 实现要点（改这个脚本时别踩）

| 点 | 说明 |
|---|---|
| **按面排序，不是按元素** | 一个大元素的不同面深度差很大，只按元素排序会出现近面被远面盖住。取每个面四顶点的中心算深度。 |
| **仿射变换解 3×3 方程** | `x = a·u + b·v + c` / `y = d·u + e·v + f`，用三个点解两组系数；逆向用 2×2 求逆。矩阵维度搞错会报 `Last 2 dimensions must be square`。 |
| **重心坐标判断像素归属** | 数组是 `(h,w,2)` 时要用 `p[...,0]` 取 x，写成 `p[0]` 会拿到整行。 |
| **数组要可写** | `np.asarray(canvas)` 是只读的，用 `np.array(..., copy=True)`；写入用 `np.where(mask[...,None], new, old)`。 |
| **parent 链递归** | 模型常只给 textures + parent，elements 在父模型里。递归合并 textures，elements 取第一个有值的。 |
| **投影居中** | 用包围盒中心 `(mx,my,mz)` 反推偏移：`ox = S/2 - (mx-mz)·cos30·scale`、`oy = S/2 - ((mx+mz)·sin30 - my)·scale`。 |

**效果对比**（同一批方块）：

- 四面平均色近似：只能看出「一大块灰色」
- 模型渲染：能看清显示器是黑屏、扫描区是绿色网格、桌子是木板 + 白羊毛台面

### 5.4.1 实体图标：不要自己渲染

**试过了，行不通，别再来一遍。** 从反编译的 Java 模型类还原实体外观走过一遍完整流程：
解析 `addBox` / `setRotationPoint` / `setRotateAngle` / `addChild`，等轴测投影，
UV 图集贴图。结果只有结构极简的模型能出图，带动画的模型全散成方块。

失败的原因有三层，都不是调参能解决的：

1. MC 的 `addChild` 把父的 rotationPoint 累加到子身上，渲染时子级又继承父的变换——
   位置算两次。模组作者的参数往往是按这个「错位」调的，按标准语义实现反而更错。
2. `setAnimationXxx` 里的分支会改 rotationPoint 与旋转角，静态解析只能拿到初始姿态，
   跟游戏里渲染出来的样子不是一回事。
3. 实体纹理是非标准尺寸的 UV 图集（600×320 之类），逐面 UV 方向要一个个对，成本极高。

**正确做法**：实体图标留空、勾选「删除大小图标」本身就是合规的（§6.7）。
真要实体图标，只有 IRR 在游戏里渲染这一条可靠路径（见 IRR 格式参考）。

> 曾经写过 `render-entity-model.py` 与 `render-humanoid.py`，两个都已删除。

### 5.5 `scripts/render-block-iso.py` — 方块等轴测立体图标

```bash
python scripts/render-block-iso.py --top top.png --side side.png --out icon.png --size 32
```

方块资料**必须**交立体图标（依据见 §图标规范第 2 条），只交 `textures/block/*.png` 的平面图会被退回「需要上传立体图标，提交的是单面纹理」。

几何参数（踩过的坑）：

| 参数 | 值 | 说明 |
|---|---|---|
| 顶面半宽 `w` | `size * 0.42` | 四周留 8% 边距 |
| 顶面半高 `hh` | `w / 2` | 2:1 等轴测菱形 |
| **侧面高 `sh`** | **`w`** | **不能写 `0.75w`**——那样总高只有总宽的 87.5%，图标看起来明显偏扁 |

明暗系数：顶面 1.0 / 左面 0.8 / 右面 0.6。渲染流程是 512 超采样后 `fit()`：放大用 NEAREST、缩小用 LANCZOS。

默认额外输出 `-128.png` 预览图。**交付前一定先打开预览图看比例**——等轴测最容易出的错就是比例算错，看缩略图一眼能发现。

### 5.6 `scripts/gen-items.py` — 批量新增的数据文件

```bash
python scripts/gen-items.py --assets "<mod>/src/main/resources/assets/<ns>" --namespace <ns> \
    --category "<资料分类>" --maxstack 1 --out items.json
```

扫 `textures/item/`（**单数**，Forge 惯例）拿物品清单，配 `lang/zh_cn.json` 与 `en_us.json` 取中英文名，把 16×16 纹理 NEAREST 放大到 32×32 转裸 base64。

两个已知限制，遇到要手改：

- **Fabric 模组多用 `textures/items/`（复数）**，脚本会报「找不到纹理目录」。此时把 ITEMS 清单写死更省事（参考 `gen-baby-items.py` 的写法）；
- **方块不在 `textures/item/` 里**，脚本天然漏掉。方块的图标要走 `render-block-iso.py` 渲染立体图，不能直接套 `b64_png()`。

`gen-baby-items.py` 是「写死清单 + 方块走等轴测」的完整范例，可直接改成别的模组用。

## 7 常见坏表与坑

从编辑器复制出来的表格常是残骸：**每个单元格被拆成 4 行**、续行省略首列、表中间插 `| --- |`。修复顺序：① 按列数重建规整表（逐行补全首列）→ ② 用 `rowspan.py` 合并 → ③ 只修粘贴损坏，不修作者文字。

| 坑 | 症状 | 解 |
|---|---|---|
| setext 标题线 | `==========` / `---------` 被当正文 | 删，改 `#` |
| 转义残留 | `\[h3=…\]`、`\= 100` | 去掉反斜杠 |
| 单元格内换行 | 表格列错位 | 重建 |
| 编号后全角标点 | `Ⅰ、`、`1、` | 改 `Ⅰ. `、`1. ` |
| `[icon:]` 后多写"点" | "20 点点血量" | 删多余的"点" |
| 表头写成 `td`+`<strong>` | 编辑器改成 `<th>`，`class="firstRow"` 被丢 | 直接输出 `<th>` |
| 裸 URL 不进 `<a>` | 链接变成纯文本 | 写成 `[url](url)` |
| 没有版本号 | 数值类页面必被退（第 23 条） | 加"数值基于模组〈版本号〉" |
| 吐槽类内容 | 纯玩梗无机制（第 8 条） | HTML 打不了吐槽标记 → 提醒用工具栏「吐槽」遮住 |
| 多页重复同段 | 第 33 条 | 拆页：资料页留简介，深度内容进教程 |
| 为消掉目录根节点去删 `[h1=]` | 首节没标题了，内容并进页面顶部 | **别删**；层级问题先问用户（§2.3 / §2.4） |

## 8 提交前校验

```powershell
$h = Get-Content "输出.mcmod.html" -Raw -Encoding UTF8
([regex]::Matches($h,'\[h[1-6]=')).Count          # 标题数
([regex]::Matches($h,'<table>')).Count             # 表数
([regex]::Matches($h,'<th>')).Count                # 表头格数 = 各表列数之和
([regex]::Matches($h,'firstRow')).Count            # 必须 0
([regex]::Matches($h,'<tr')).Count                 # 行数 = 表头 + 数据行
([regex]::Matches($h,'rowspan="\d+"')).Count       # 合并格数
([regex]::Matches($h,'<blockquote|<code>')).Count  # 必须 0
($h -split "`n")[0]                               # 首行应是 title_menu 指令；裸文本或 <p> 包裹都行
```

另外：替换过的术语要扫残留；行数要与源表数据行数对得上。

## 9 交付话术

三段，别写成流水账：

1. **改了什么** —— 表格列"原文问题 → 现在"，方便逐条核对；
2. **校验数字** —— 标题/表格/行数/`<th>`/残留 0；
3. **需要你拍板** —— 分类是否同意、哪句重写了、哪条数据存疑、哪些要手动用「吐槽」遮。

同成交 **HTML（主）+ Markdown 源稿**，并明确写：**「粘贴前请在编辑页顶部勾选『源代码编辑器』」**（Markdown 编辑器表达不了合并单元格与颜色）。不要宣称"已合规"，只报事实与待定项。

---

**分发方式：优先油猴脚本，不要默认打包扩展。** `scripts/mcmod-batch.user.js` 本身就是标准
UserScript（含 `@match`、`@run-at document-idle`、IIFE 包裹），装进 Tampermonkey 即可，
**不需要开发者模式**；打包成扩展反而逼用户开 `edge://extensions` 的开发者模式，是绕远路。

| 方式 | 开发者模式 | 适用 |
|---|---|---|
| 油猴脚本（推荐） | 不需要 | 日常使用，脚本更新只需改粘贴内容 |
| 书签小工具 `javascript:` | 不需要 | 不想装扩展时，一次点按注入面板 |
| 打包扩展 | **需要** | 仅当需要常驻、自动注入才用 |

给用户写安装说明时，先给油猴路径；只有对方明确要求常驻扩展才提第三种。





### 绑定热键：注册名留空，不要填本地化 key

**退回原话**：「注册名填错了…当前提交的是本地化 key」。

这是 §「注册名与原名都是必填项」的唯一例外类型——热键没有注册表 id，留空是正确的；
填了本地化 key 反而会被判错。

- 热键的「注册名」字段**留空**即可；
- 按键映射的 `key.<modid>.<动作>` 是**本地化键**（用于 lang 文件与「控制」界面显示），
  不是注册名，填进去会被判错；
- 同理，`effect.<modid>.<id>`、`entity.<modid>.<id>` 这些也属本地化键，只有**真正的注册表 id**
  （`modid:xxx`）才算注册名。

### 批量填表必须「有值才写、没值清空」

只写「条目里有值的字段」会**保留上一条的残留**。实测：连续提交 5 条热键时，
第 5 条「试听语音」的次要名称带出了上一条 BUFF 的英文名 `Eternal Utopia`。

正确写法：

```js
function clearOrSet(el, v) {
  if (!el) return;
  if (v === undefined || v === null || v === '') { /* 置空 + 派发 input/change */ }
  else setVal(el, v);
}
clearOrSet(qm('ename'), it.ename);
clearOrSet(qm('regname'), it.regname);
```

### 方括号标记的摆放规则（审核实测）

> 这两条警告（「标题较少，是否需要标题目录禁用标记」「含有跨级使用的标题」）
> 在**新增（/item/add/）**和**编辑审核中（/item/edit/…-<审核项>）**两条路径上都会做同样的校验，
> 不是只针对新增。修法一致：`[ban:title_menu]` 独占 `<p>` 放最前 + 标题从 `[h1=]` 起。


**`[ban:title_menu]` = 标题目录禁用标记**

- 作用是**关掉正文右侧的标题目录**；标题本来就少的页面（资料页、短设定页）加上它，可以消掉
  审核的「正文介绍中的标题较少，请判断是否需要添加标题目录禁用标记」这条警告；
- **必须独占一个 `<p>`，并放在正文最前面**：
  ```html
  <p>[ban:title_menu]</p>
  <p>[h1=羁绊系统]</p>
  <p>[h2=概述]</p>
  ```
- **不能和别的标记挤在同一个 `<p>` 里**（写成 `<p>[ban:title_menu][h2=概述]</p>` 会被判结构错误）。

**标题必须从 `[h1=]` 开始**

- 正文里第一个标题若是 `[h2=…]`，会触发「正文介绍中含有跨级使用的标题，请检查标题结构完整性」；
- 正确层级：`[h1=页面名]` → `[h2=分节]` → `[h3=子节]`，不要跳级；
- 每条资料页的正文都要自带 `[h1=]`（**不要只在说明文档或合订本里加**——提交的是 JSON 里的 html，
  合订本加了、JSON 没加，提交上去照样报跨级）。

**所有 `[hN=…]` 与 `[ban:…]` 标记都必须各自独占一个 `<p>`。**

### 批量导入 JSON 的顶层必须是数组

新增页批量面板的判断是 `if (!Array.isArray(arr)) throw new Error('顶层必须是数组')`。

- 正确：`[ {资料1}, {资料2} ]`
- 错误：`{ "classId": "25431", "items": [ … ] }` → 面板报「载入失败：顶层必须是数组」

需要携带 classId 之类的元信息时，单独写一个说明文件，别塞进导入 JSON。
（编辑计划 `/item/edit/` 那套是例外：脚本兼容 `raw.items || raw`，两种都吃。）

### 画廊 / 图片表格的官方写法

模组介绍页里的多图展示不是「一堆 `<img>` 竖排」，而是**用 `<table>` 排成的图片网格**
（真实样例来自"自然之灵"介绍页）：

```html
<table width="861" style="width: 1292px;">
  <tbody>
    <tr>
      <td width="331"><img src="https://i.mcmod.cn/editor/upload/20230909/xxx.png"
           title="xxx.png" alt="xxx.png" width="480" height="300" _src="https://i.mcmod.cn/editor/upload/20230909/xxx.png"></td>
      <td style="word-break: break-all;" width="331"><img ...></td>
      <td style="word-break: break-all;" width="331"><img ...></td>
      <td style="word-break: break-all;" width="331"><img ...></td>
      <td style="word-break: break-all;" width="331"><img ...></td>
    </tr>
    <tr> … 第二行 5 张 … </tr>
  </tbody>
</table>
```

要点：

- **一行 5 张**是常见密度；`<td width="331">` + `style="word-break: break-all;"`（第一格可省 style）；
- `img` 必须同时带 `src` / `title` / `alt` / `width` / `height` / `_src` 六个属性，
  `title`、`alt`、`_src` 三处都填**同一个文件名**（UEditor 上传后自动生成的行为）；
- 图片只能来自 `https://i.mcmod.cn/editor/upload/<日期>/...` —— **必须先通过编辑器上传**，
  外链图片会被审核要求替换；
- 表格外层 `width` 与 `style="width: …px"` 可能不一致（UEditor 拖拽后的残留），照抄即可，不用纠正。

### 页面结构标记（正文里用方括号占位）

```
<p><img …></p>            首图（横幅）
<p>[h1=概述]</p>          一级标题
<p>[h2=特点]</p>          二级标题
<p>[h2=其他]</p>
<p>[h1=画廊]</p>          画廊标题
<table>…</table>          画廊本体
<p>[ban:title_menu]</p>   去掉右侧资料目录（长页里用得少，短页可加）
```

- `[hN=标题]` 必须**独占一个 `<p>`**；
- 列表用 `<ul style="list-style-type: disc;" class=" list-paddingleft-2">`（注意 class 前的空格是站点原样）；
- 站内引用用绝对地址，如 `<a href="https://www.mcmod.cn/item/786235.html" target="_blank">高岭土</a>`，
  同一模组内的资料列表页链接形如 `/item/list/12113-8.html`。

### 矿物词典（tag）怎么填

> **实测（2026-10）**：填 `#curios:finality` 被审核退回，理由「确定开头带 # 嘛？」。
> 正确写法是**不带 `#`**：`curios:finality` / `lastsongofelysian:herrscher_cores`。
> 页面上看到的 `#` 是标签控件自己渲染的前缀，自己写反而重复。


「矿物词典」字段接受 **`命名空间:标签名`** 形式（**不要加 `#`**），多个用逗号分隔。
值必须来自模组 `data/<ns>/tags/items/*.json` 的定义，**不要自造标签**。

乐土终曲（Last Song of Elysian）的四个物品 tag：

| tag | 文件 | 成员 |
|---|---|---|
| `#lastsongofelysian:herrscher_cores` | `data/lastsongofelysian/tags/items/herrscher_cores.json` | 13 个律者核心 |
| `#curios:signets` | `data/curios/tags/items/signets.json` | 13 个刻印（含真我） |
| `#curios:remembrance_sigils` | `data/curios/tags/items/remembrance_sigils.json` | 45 个追忆之证 |
| `#curios:finality` | `data/curios/tags/items/finality.json` | 终焉之茧 |

生成脚本：`build_tags.py`（读 tag json → 回填导入数据的 `oredict` 字段）。

### 编辑已有资料：改动附言与改动说明都必须写

- **改动附言（仅管理员可见）必写**，说明改了什么、依据是什么，**结尾接「辛苦 XXX 机了」**（变体规则见 §6.2.3，不是写死的四个字）；
- **改动说明（所有人可见）**给读者一句话总结；
- 批量工具里对应字段 `editRemark` / `editNote`，两者都不写会显得敷衍，审核也可能退回。

示例：

```
editRemark: 按模组源码的 tag 定义补充矿物词典：追忆之证（curios:remembrance_sigils）。
            依据是模组数据包 data/*/tags/items 下的定义，未添加源码中不存在的标签。辛苦喵呜机了
editNote:   补全矿物词典：追忆之证（curios:remembrance_sigils）（依据模组 tags/items 定义）。
```


### 资料列表页只渲染一部分条目：必须跟进「查看更多」

**实测（[SI]奇点迭代，classId 28898）**：页面顶部写「物品/方块 (651)」，
但主页面 HTML 里只有 **422** 个 `/item/<id>.html` 链接；分类 `材料`/`机器`/`工具`
的末尾各有一个「查看更多」，指向 `/item/list/<classId>-<type>-<分类id>.html` 子页，
把三个子页抓下来并集后是 **482** 条 —— 仍少于 651。

- 差异来自**合并项**（页面里 `<span class="skip">-(<li>…</li>)</span>` 包着的同组资料）
  与可能的多版本计数，页面上没有对应可点链接，任何抓取器都拿不到；
- 结论：**以实际抓到的链接数为准**，不要拿页面顶部数字当校验目标；
- 读取器 v2.33 起会自动跟进 `a.more[href*="/item/list/"]` 子页（最多两层、去重），
  并把进展写进面板日志（`跟进「查看更多」子页 N 个，累计 X 条…`）。

### 多级分类与 rowspan 合并（资料列表页的真实写法）

大型模组的物品分类会是**多级嵌套**，百科列表页的呈现方式是：

1. **左侧分类导航**用冒号拼路径，并带计数：
   ```
   一般饰品 (29个)
   一般饰品:机械仿生 (8个)
   一般饰品:机械仿生:邪母 (16个)
   一般饰品:铸造幽影:混沌理论 (8个)
   信仰 (8个)
   ```
2. **右侧表格用 rowspan 合并**：上级分类只出现一次（纵向合并整块），
   下级分类各占一行；叶子层的物品按 `ul > li` 平铺在对应行右侧。

对写资料的含义：
- 「资料分类」字段应当填**完整的冒号路径**（`一般饰品:机械仿生:邪母`），
  只填叶子名（`邪母`）会挂到错误层级或不存在；
- 我们自己的导入 JSON 里 `category` 也按这个路径写，批量脚本的 `#item-type-custom`
  直接填整串即可；
- 生成 HTML 时若要做同类表，用 `<td rowspan="N">` 合并上级分类，不要重复写。

（这条只作知识记录：当前乐土终曲的 94 个物品分类是单层的，不需要多级。）

### 资料列表页（`/item/list/<classId>-<type>.html`）结构

批量编辑的入口。实测结构（2026-10）：

```
table.item-list-table.item-list-table-<classId>-<type>
├─ thead th[colspan=2]
│   ├─ span.title > a[href="/class/<classId>.html"]
│   ├─ div.item-list-switch-fold[data-type="1"]
│   └─ ul.item-list-switch
│       ├─ a.item-list-switch-lang       显示次要名称
│       ├─ a.item-list-switch-skip       隐藏合并项
│       └─ a.item-list-switch-quickedit  快速编辑（点后条目旁出现「编辑 / 加合成」）
└─ tbody > tr
    ├─ th.item-list-type-left            分类名（可能是链接）
    └─ td.item-list-type-right ul li span a[href="/item/<资料id>.html"]
         文本 = 中文名；data-en = 英文名 **或** 注册名（不统一，不能当主键）
```

- **资料 id 从 href 提取**：`/item/1028243.html` → `1028243`，这是编辑页 URL `/item/edit/<id>/` 需要的；
- `data-en` 实测三种：注册名（`core_of_reason`）、英文名（`Abyss Flower`）、带扩展名的文件名（`xxx.png`）；
- 条目总数可能大于页面顶部统计（隐藏合并项/「查看更多」）。

**脚本已实现（v2.6，只读第一阶段）**：列表页右上角注入面板 →「读取列表」抓出 `分类/名称/英文/资料 id`，
「切换快速编辑」后自动收集 `a[href*="/item/edit/"]`，「复制/下载 JSON」得到待编辑清单。

**第二阶段（跨页批量编辑）设计**（未实现，需先单条验证）：
```
列表页：读取 rows → 载入待编辑 JSON → sessionStorage{queue,index,fields} → location.href='/item/edit/<id>/'
编辑页：检测待办 → 复用 fillOne() 填字段 → 提交 → index++ → 回列表页
```
编辑页与新增页表单结构一致（同样 `[data-multi-id=...]` / `#icon-32x` / CodeMirror），
但**编辑是覆盖式**：必须先单条验证「提交后不会产生重复条目、不会清空未填字段」。

### 5.7 批量面板（`mcmod-batch.user.js`）支持的页面与队列

同一个脚本管五种页面，靠 `location.pathname` 分流：

| 页面 | 用途 | 面板 |
|---|---|---|
| `/item/add/<classId>/` | 批量新增资料 | 蓝色「批量新增」 |
| `/item/list/<classId>-<type>.html` | 读取列表与编辑链接 | 列表面板 |
| `/item/edit/<id>/` | 批量编辑已有资料 | 蓝色「批量编辑」 |
| **`/class/edit/<classId>-<subId>/`** | **模组介绍再编辑** | 绿色「模组介绍 · 批量编辑」 |
| `/verify*` | 审核列表读取 | 验证面板 |

#### 三个必须知道的机制

**① `@match` 漏一个页面，脚本就不会加载**

扩展版还要同步 `manifest.json` 的 `content_scripts.matches`。
`/class/edit/*` 是 v2.40 才补上的 —— 之前模组编辑页「面板消失」的根因就是这个，
不是面板被清掉，是脚本压根没注入。

**② 队列存在 sessionStorage 的全局键里，不要按 classId 分开存**

```
mcmod-class-edit-plan = { items: [...], autoRun, paused }
```

早期按 `mcmod-class-edit-<classId>` 分开存，翻页后对不上就「丢 JSON」。
现在整份存一处，每页按 `classId` 取自己那条。

**③ 自动跳转必须有 `targetUrl`，而且猜不出来**

再编辑页 URL 是 `/class/edit/<classId>-<verifyId>/`，**第二段是随机 id**，
同一个模组每次退回都不一样。只能从审核列表的 `againHref` 取：

```
{"classId": 2674, "name": "Bunny Boots",
 "targetUrl": "/class/edit/2674-818373/", ...}
```

没有 `targetUrl` 就只能手动翻页，「连续执行」走不下去。

#### 连续执行流程

```
填入正文 + 附言 + 说明 → 提交 → 等 2.6s → 点确认 → 等 2.8s
   → 按下一条的 targetUrl 跳转 → 新页面加载 2s 后自动重复
   → 队列跑完提示「队列完成」
```

找不到提交按钮或等不到确认框 → 自动 `paused`，不会盲点。
「停止」保留队列，可再点「连续执行」续跑。

#### 改了脚本之后

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1      # 同步到技能目录
python scripts\install-extension.py                          # 重建扩展（MV3）
# 再去 edge://extensions 点「重新加载」
```
