## 0 安装

### 0.1 装本技能

把整个 `mcmod-page` 文件夹放进技能目录：

| 平台 | 路径 |
|---|---|
| Windows | `%USERPROFILE%\.dsh\skills\mcmod-page\` |
| macOS / Linux | `~/.dsh/skills/mcmod-page/` |

最终结构（`scripts/` 必须一起放，别只放 SKILL.md）：

```
mcmod-page/
├── SKILL.md
├── README.md
└── scripts/
    ├── md2mcmod.py     # Markdown -> 百科 HTML
    ├── rowspan.py      # 表格首列合并成 rowspan
    └── 示例-源.md      # 可跑的最小示例
```

重启会话（或新开一个），说「帮我优化这个百科页」就会命中；也可以显式 `skill mcmod-page`。
其它客户端（Claude Code、Cursor 等）把同样的文件夹放进它自己的 skills 目录即可——格式就是 Markdown + frontmatter，通用。

### 0.2 建议一起装：Windows MCP（让 agent 把该装的都替你装好）

它给 agent 一条"能看见屏幕、能点能打字"的桌面通道。在这套流程里，它按顺序干三件事，**你只在开头同意、结尾看一眼**：

| # | agent 会做 | 你要做的 |
|---|---|---|
| 1 | **装篡改猴**：打开扩展商店页 → 点「获取 / 添加」→ 确认弹窗 → 到扩展详情页打开「允许用户脚本」（不开的话脚本装了也不会执行） | 同意一次 |
| 2 | **装 MC百科脚本**：[Mcmodder 直链](https://github.com/Charcoal-Black/Mcmodder/releases/latest/download/mcmodder.user.js) → 篡改猴弹安装页 → 点「安装」→ 回「已安装脚本」核对版本号与「已启用」 | 无 |
| 3 | **粘稿子**：打开百科编辑页 → 切「源代码编辑器」→ 粘贴生成的 HTML → 点预览 → 保存 → 截图给你 | 看一眼 |

没有它，这三步都得你自己来：自己装扩展、自己装脚本、自己粘几十 KB 的 HTML。

安装（Windows，需 Python 3.10+）：

```powershell
# 1) 装，任选其一
pip install uv            # 若还没装 uv
uvx windows-mcp serve     # 不常驻，uv 每次自动拉最新版
# 或
pip install windows-mcp   # 常驻安装
windows-mcp serve         # stdio 方式启动
```

```yaml
# 2) 在客户端的 MCP 配置里注册（以 DSH 为例：<profile>/cordis.patch.yml）
- insert:
    - id: mcp-windows
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: windows
        transport: stdio

        command: 'windows-mcp'

        failOnStartupError: false
```

3. 重启客户端，工具列表里应出现 `mcp__windows__*`（Snapshot / Click / Type / Shortcut / PowerShell 等）。
4. 首次调用会稍慢（装依赖），官方提示首次可能超时，重试即可。

项目地址：<https://github.com/CursorTouch/Windows-MCP>（PyPI 包名 `windows-mcp`）。

> **安全提醒，必须看。** 这个 MCP 等于把桌面控制权交给 agent：它能截屏看到你的屏幕、能点击和输入。
> 建议在专用账号或虚拟机里用；用前关掉敏感窗口（网银、密码管理器）；只在你盯着的时候开，用完就停。
> 第 1、2 步在改动你的浏览器扩展（安装扩展、授予脚本权限），属于"要你知情"的改动。

> **操作要点**（给 agent）：动手前先 `Snapshot` 看屏幕；开网址用 `Shortcut('ctrl+l')` + `Type(url)`，比找地址栏稳；点击前先截图核坐标（估错会点飞，误点可能跳到别的页面）；装完不能只看"点了没报错"，要回篡改猴列表核对版本号与「已启用」。扩展类改动**每步做完截图给用户确认**，不要一口气跑完。

装好技能后、第一次干活之前，**问一次**（问过就别再问）：

> 要不要我顺手把 **Windows MCP** 装上？装上之后，装篡改猴、装百科脚本、粘稿子这几步都由我来做，你只在开头同意一次、结尾看一眼。
> 不装也行，这三步我教你手动做。

| 用户回答 | agent 做什么 |
|---|---|
| **已经装了** | 直接进 §1 干活，之后不再提 |
| **要装** | 按 §0.2 装（`pip install uv` → `uvx windows-mcp serve`，或 `pip install windows-mcp`），再往客户端 MCP 配置里加 `mcp-windows` 条目；重启客户端，确认工具列表出现 `mcp__windows__*`，然后开工 |
| **不装** | 说明代价 + 给人类手动清单（见下），然后继续用脚本产出 HTML。**不要反复劝** |

**不装时的代价**：技能仍能跑脚本（转换 / 合并 / 校验），但下面三件事得用户自己做：

1. 自己装**篡改猴**（扩展商店搜索安装），并到扩展详情页打开「允许用户脚本」——不开则脚本装了也不执行。
2. 自己打开 [Mcmodder 直链](https://github.com/Charcoal-Black/Mcmodder/releases/latest/download/mcmodder.user.js) 点「安装」，再回篡改猴「已安装脚本」核对版本号与「已启用」。
3. 自己打开百科编辑页 → 切「源代码编辑器」→ 粘贴生成的 HTML → 预览 → 保存。

**为什么必须先问、不能默认装**：

- 本技能的产出全靠**实际执行脚本**——没有本地执行能力，它就退化成"给一段文本让用户自己跑"。
- 若客户端本来就有 shell / PowerShell 工具，那装 Windows MCP 的收益只剩"操作浏览器"这一点；问的时候要说清，别让用户以为不装就跑不了脚本。
- 装 MCP 等于把桌面控制权交出去，还会改动浏览器扩展——这是要用户知情并同意的改动，不是顺手就做的事。

## 10 本地改写模型（训练与配置）

目标：把 AI 味草稿改成符合主站规范的正文。这一节记录**为什么训、怎么训、训出来什么水平**。

### 10.1 为什么需要这个模型

AI 生成的模组介绍有三个典型毛病：

| 毛病 | 例子 |
|---|---|
| 套话连接词 | 「值得注意的是」「与此同时」「总的来说」 |
| 空洞抽象 | 「改变互动节奏」「更像一次战术决策」 |
| 格式违规 | emoji、堆叠标点、`PS.` 前后缀 |

为什么不用规则或大模型 API：

- **规则检测不可靠**：实测 35 条判定里 34 条误报（营销腔/口号/感叹号都是人类正常写法，不能当 AI 判据）
- **大模型 API**：每次要联网、要付费，批量处理成本高
- **本地小模型**：一次训练，无限次调用，零边际成本

**但必须明确它的定位**：

> 模型是**润色工具**，不是**作者**。
> 它能把好草稿改得更规范，**不能把空话改出实质内容**。

### 10.2 数据从哪来

不是随便扒的语料，而是**筛选过的真实百科正文**：

```
全库抓取 10,095 个模组页面
  ↓ 格式筛选（去 emoji / 堆叠标点 / 分割线 / markdown 残留）
7,858 条
  ↓ 要求 ≥300 字 + 有分节（n_headings ≥ 1）
3,673 条
  ↓ DeepSeek 逐条判断内容（264 万 token）
排除 34 条空洞页面
  ↓ 只保留评分 ≥85 的
2,789 个模组
  ↓ 按段落切分（250–700 字/样本）
3,283 训练 + 416 验证 + 420 测试
```

额外纳入用户指定的 `class/1`（我的世界原版）作为基准样本。

**每条训练样本**：

```json
{
  "prompt": "你是 MC百科编辑…【主站规范 10 条】…待改写：<AI 味版本>",
  "chosen": "<真实百科正文>",
  "rejected": "<程序注入 AI 味的版本>"
}
```

`rejected` 由 `scripts/ai-tell-inject.py` 自动生成：随机插入套话前缀、三连排比、升华结尾、空洞形容词、句长均匀化、模板化收尾。实测 83% 的 rejected 含明显套话。

### 10.3 训练配置

**硬件**：AutoDL / 矩池云 的 **V100-32GB**（1.98 元/时）
**耗时**：SFT 约 3.5 小时，成本约 7 元
**镜像**：`PyTorch 2.5.1 / Python 3.12 / CUDA 12.4`

```bash
pip install -i https://mirrors.aliyun.com/pypi/simple/ \
  "transformers==4.46.3" "trl==0.12.2" "peft==0.13.2" "datasets==3.2.0" \
  accelerate bitsandbytes sentencepiece
```

**超参数**：

| 项 | SFT | ORPO | 说明 |
|---|---|---|---|
| LoRA r | 16 | 16 | rank 越高拟合越强，16 是 7B 的常用值 |
| lora_alpha | 32 | 32 | 一般 = 2×r |
| lora_dropout | 0.05 | 0.05 | 防过拟合 |
| target_modules | q/k/v/o/gate/up/down_proj | 同 | 覆盖注意力 + MLP 全部线性层 |
| 量化 | QLoRA 4bit (nf4, double quant) | 同 | 7B 只占 6.7 GB 显存 |
| learning_rate | **2e-4** | **5e-5** | ORPO 是对比学习，学习率要低 4 倍 |
| epochs | 3 | 1 | ORPO 每步更慢（算 chosen+rejected 两组） |
| batch | 2 | 1 | ORPO 显存更吃紧 |
| grad_accum | 8 | 8 | 等效 batch 16 |
| max_len | 2048 | 2048 | 再长会截断正文 |
| beta | — | 0.1 | ORPO 偏好强度 |

**训练脚本**：`scripts/train-orpo.py`（`--mode sft` / `--mode orpo`）

### 10.4 模型对比（12 条固定难样本实测）

| 模型 | 信息保留率 | 套话均数 | 显存(4bit) | 加载耗时 |
|---|---|---|---|---|
| base 0.5B | 0.687 | 2.75 | ~1 GB | 2 s |
| **SFT 0.5B** | **0.897** | 0.17 | ~1 GB | 2 s |
| base 1.5B | 0.736 | 1.67 | ~2 GB | 3 s |
| SFT 1.5B | 0.874 | 0.50 | ~2 GB | 3 s |
| base 7B | — | — | ~6.7 GB | 12 s |
| **SFT 7B** | **0.902** | **0.00** | **~6.7 GB** | **12 s** |
| ORPO 7B | 同 SFT | 同 SFT | ~6.7 GB | 12 s |

「信息保留率」= 原文里的数字/英文专名在改写后保留的比例，越高越安全（改错数字是硬伤）。

**结论**：

- **7B SFT 最优**（套话彻底清零），但只比 0.5B 高 0.5 个百分点
- **0.5B 性价比最高**（显存 1 GB，速度快 6 倍，效果已经够用）
- **ORPO 无优势**（输出与 SFT 逐字相同）—— 因为训练数据里的 rejected 是「表层套话」，不是「结构性空洞」
- 8 GB 显卡跑 7B 需 4bit（占 6.7 GB），只剩 1.3 GB 给 KV cache，**输出控制在 800 字内**

### 10.5 怎么用

```powershell
# 一键脚本（推荐）
cd E:\Mod\百科-语料
.\改写.ps1 草稿.md                 # 7B SFT 改写
.\改写.ps1 草稿.md -CheckOnly       # 只看评分不改写（秒出）
.\改写.ps1 -Interactive             # 交互模式，反复试
.\改写.ps1 草稿.md -Model 0.5b      # 小模型（1 GB 显存）
```

输出包含：改写前评分 → 改写后评分 → **信息保留率**（<90% 会警告）。

底层脚本 `scripts/rewrite.py`，参数：

```powershell
& $py "scripts\rewrite.py" 草稿.md `
  --model "7B基础模型路径" --lora "LoRA路径" --max-new 800
```

### 10.6 能力边界（必须知道）

| 能做 | 做不到 |
|---|---|
| 删套话连接词（值得注意的是/总的来说/无疑） | **补缺失的事实** |
| 调整句长、去堆叠标点 | **判断内容真假** |
| 保留 90% 数值与专名 | **把空话改写成实话** |
| 按主站规范格式输出 | **无中生有写机制** |

**实测反例**：拿一篇 753 字、零具体机制的 AI 生成稿（`class/25177`）喂给 7B SFT，输出 772 字里**只删掉 1 个「与此同时」**，其余一字未改。

原因：模型学的是「删表层套话」，而这篇的问题是「没有内容」，两回事。

**正确的工作流**：

```
1. 拿到事实依据（jar 分析 / 官网 / 其他资料）
   ↓
2. 用模型把事实组织成规范文本
   ↓
3. 人工核对数值与术语
```

没有原料，模型做不出饭。

### 10.7 训练踩过的坑

| 坑 | 现象 | 解法 |
|---|---|---|
| **阿里云 PyPI 的 torch 是 CPU 版** | pip 装出 `torch 2.15.0`（假版本），把 CUDA 环境换掉 | 装 torch 只用官方源 `download.pytorch.org`；或用 `-c constraints.txt` 锁死 torch 版本 |
| **transformers 版本过高** | 5.x 要求 torch ≥2.6，与 2.5.1 冲突 | 锁 `transformers==4.46.3` |
| **trl 1.x 删掉了 ORPO** | `ImportError: cannot import name 'ORPOTrainer'` | 锁 `trl==0.12.2`（有 ORPO） |
| **numpy 被升到 2.x** | 某些 torch 版本报 ABI 错误 | 实测 torch 2.3/2.5 + numpy 2.5 可用；报错就 `pip install "numpy<2"` |
| **Windows 上 bitsandbytes** | 默认装不上 | `pip install bitsandbytes`（0.50.2 支持 Windows + 4bit，实测可用）|
| **临时目录有 `timeit.py` 之类文件** | `ImportError: cannot import name 'default_timer' from 'timeit'` | 别在 `$env:TEMP` 存与标准库同名的脚本 |
| **1.5B 给 2048 序列长度会 OOM** | 8 GB 卡跑不动 | 降到 1536，或改用 4bit |

### 10.8 什么时候需要重训

**结论：当前模型够用，不需要重训。**

理由：

1. 7B SFT 保留率 0.902、套话 0.00，已达到「润色工具」的上限
2. 再扩数据（候选池 9,000+）对保留率的提升有限（0.5B→7B 也只涨 0.5 个百分点）
3. 真正的瓶颈是**事实来源**，不是模型能力

只有以下情况才值得重训：

- 目标变成「批量改写数千条」（需要更高吞吐）
- 训练数据扩到 15,000+ 条（量变可能引发质变）
- 换了更好的 base 模型（如 Qwen3）
