# 交付示例

四个真实交付，给别的机器当参照。**不要直接抄内容**，抄的是结构与字段。

| 文件 | 是什么 | 看点 |
|---|---|---|
| `01-单物品模组-介绍.html` | 单物品模组的模组页 | 只有 1 个 h1 + 2 个 h2，`[ban:title_menu]` 放第一行 |
| `02-单物品模组-物品.json` | 对应物品页 | 5 字段白名单，`[icon:hunger-level=…]` 的写法 |
| `03-多物品模组-介绍.html` | 31 件物品的模组页 | 内容已下沉到资料页，模组页只留概述 + 一张成本表 |
| `04-通用文本.json` | 承接整族重复正文的隐藏资料 | `category` 用 `{文本}`，图标与注册名留空 |
| `05-物品导入-引用通用文本.json` | 31 条引用通用文本的物品页 | 正文只留「本件是哪个」，数值用 `[icon:…]` |
| `06-批量再编辑-模组介绍.json` | 批量再编辑模组介绍 | `classId` + `targetUrl`（自动跳下一条要用） |

## 对应的坑

- **03 为什么这么短**：原来把 22 种罐子的数值全列在模组页，审核要求
  「对单个资料的详细描述写到资料页，模组正文仅需摘要」
- **04/05 为什么这么分**：22 条正文里「合成」那段一字不差，重复率 14%，
  建通用文本承接，各条只留饥饿值与饱和度
- **06 的 `targetUrl`**：格式是 `/class/edit/<classId>-<verifyId>/`，
  第二段是随机的，**猜不出来**，必须从审核列表的 `againHref` 里取
